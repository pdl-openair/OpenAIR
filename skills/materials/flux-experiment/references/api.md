# 云实验平台 API 契约（flux / CrystalFlux）

> 来源：平台方提供的接口说明（2026-10）。本文档记录字段原貌与已发现的歧义，供排错与后续维护使用。

## 通用约定

| 项 | 值 |
| --- | --- |
| Base URL | `http://<flux-base-url>` |
| 鉴权 | Header `X-Api-Key: <key>` |
| Content-Type | `application/json; charset=utf-8` |
| 网络 | 内网地址，非内网/VPN 环境不可达 |

## 1. 创建试验任务

`POST /open/api/v1/tasks`

请求体：

```json
{
  "templateId": "2043611007682150400",
  "taskName": "<任务名称>",
  "params": [
    { "paramName": "recommend_recipes_str", "paramValue": "<方案数组的 JSON 字符串>" }
  ]
}
```

约束：

- `templateId` 固定值 `2043611007682150400`，不可改动。
- `params` 只有一个元素，`paramName` 固定为 `recommend_recipes_str`。
- `paramValue` 是**字符串**。它承载一个「推荐实验方案列表」的 JSON 数组序列化结果，即需要两层 JSON：外层是接口 body，内层是被转义的方案数组。这是本接口最容易出错的地方。
- `taskName` 不能为空。

成功响应：

```json
{ "code": 2000, "msg": "", "data": { "taskId": "...", "taskCode": "..." } }
```

## 2. 启动试验任务

`POST /open/api/v1/tasks/{taskId}/start`，请求体 `{}`。

成功响应：

```json
{ "code": 200, "msg": "", "data": {} }
```

`data` 为空属正常——启动接口不返回业务数据，以创建阶段的 `taskId` 作为后续唯一凭据。

## 2a. 任务状态 / 结果 / 停止（2026-10-17 实测发现，平台文档未提供）

| 能力 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 查状态 | `GET` | `/open/api/v1/tasks/{taskId}/status` | 返回 `status`（数字）+ `statusLabel` |
| 收结果 | `GET` | `/open/api/v1/tasks/{taskId}/result` | 未完成返回 `code:202`；完成后 `data` 为结果 |
| 停任务 | `POST` | `/open/api/v1/tasks/{taskId}/stop`，body `{}` | 实测立即生效 |

实测语义：

- `status=3` → `进行中`；`status=4` → `已结束`（stop 后即为 4）。
- `status` 返回的 `endTime` 是**固定 7 天配额窗口**（1.6h 工艺的冒烟任务同样给 7 天），不代表实际完成时间；完成以 `/result` 不再返回 202 为准。
- `latestPollResponse` 初始为 `null`，平台产出轮询数据后会回填。
- 其他候选路径（`/cancel`、`/terminate`、`/detail`、`/query`、`GET /tasks` 列表）实测均不存在或方法不符。

## 2b. 只读目录端点（2026-10-18 实测，资源广场「设备资源」数据源）

| 能力 | 方法 | 路径 | 说明 |
| --- | --- | --- | --- |
| 实验模板目录 | `GET` | `/open/api/v1/templates` | 当前账号可见 5 个模板（含 labId/estimateDays/priority） |
| 模板参数结构 | `GET` | `/open/api/v1/templates/{templateId}/params` | 参数树（children 递归），`defaultValue` 可内嵌示例方案 JSON |
| PVD 工艺字典 | `GET` | `/open/api/v1/pvd/dict/subRecipe` | 子配方字典 14 条（groupName/subRecipeName/enabled/sortOrder） |

实测语义：

- 三端点均接受 `X-Api-Key` 鉴权，返回 `code:200`，`data` 直接是业务数组。
- `labName` 字段存在但平台未回填（为 `null`），展示层回落 `labId`。
- 存在纯数字命名的测试模板（如 `11221212`），前端作能力标签时过滤纯数字名。
- 平台偶发慢响应（实测单请求 10–40s 波动，亦有整段不可达时段）：读端点默认 10s 超时 + 1 次网络类重试；上层（资源广场）实时失败即回落本地快照，不重试长阻塞。
- OpenAIR 后端代理见 `services/api/app/modules/flux_platform_client.py`（白名单字段投影，不透传原始响应；API key 不下发前端）。

## 2c. 内部管理 API 与暴露面（2026-10-18 探测结论）

- 平台为 RuoYi-Vue-Plus（Spring Boot）。`/actuator/mappings` **无鉴权即可读**（可枚举全部路由）；建议平台方收紧 actuator 暴露范围，生产集成不要依赖它。
- bigScreen（大屏）等内部管理接口（`/screen/*`、`/system/*` 等）需要 RuoYi 用户 token（登录态），`X-Api-Key` 不可用（401）。设备实时状态、任务实例列表等数据在内部 API 里，但**未经平台用户授权不该接入**；当前集成只用 open API 三端点。

## 已知歧义与处理方式

1. **成功码不统一**：创建返回 `2000`，启动返回 `200`。脚本 `SUCCESS_CODES = {200, 2000}` 同时兼容，以实际返回为准。
2. **注释混入示例**：平台文档的 body 示例里带 `#` 注释与尾随逗号，那不是合法 JSON。自己拼字符串极易产生非法 JSON，必须走脚本序列化。
3. **字段命名混用中英文**：方案对象顶层键为中文（`方案ID`、`工艺参数`），温度程序内部键为「中文 + 英文单位后缀」（如 `最高温段保温温度_摄氏`、`降温速率_主降温_℃每小时`）。单位后缀是语义的一部分，不要改写成 `maxTempC` 之类。
4. **`参数值单位不统一**：分离温度、烧结温度为摄氏度，时间为小时，降温速率为 ℃/小时；比例字段是字符串（如 `Al:In:Se=1:1:3`、`Na:(Al+In+Se)=2.7:1`）。校验器只做解析与一致性提示，不做单位换算。
5. **`方案类型` 取值范围未在文档中枚举**：示例为 `baseline`。其他取值（optimize / control 等）需向平台确认，不要臆造。
6. **`templateId` 是 19 位数字 `2043611007682150400`**，超出IEEE754 双精度安全整数上限（2^53−1 ≈ 9.007e15）。Python 的 int 无此问题，但平台侧若是JavaScript，`JSON.parse` 会把它舍入成`2043611007682150400`→ 精度丢失的近似值，可能匹配不到模板。
   - 本skill **默认按字符串下发** `"templateId": "2043611007682150400"`，多数后端（Java/Python/Go 的 string 型主键绑定）都能正确处理。
   - 若平台明确要求数字，用 `--template-id 2043611007682150400` 覆盖；若字符串被拒（400），同样用该参数切回数字。
   - 首次上线时**务必确认平台侧实际接受的类型**，别让两种类型混着发。
7. **创建成功码 `2000` 不是标准 HTTP 语义**，平台沿用了业务码风格。不要用 `code == 200` 判断创建成功。

## 方案对象字段清单

顶层：

- `方案ID`（string，唯一）
- `方案类型`（string，如 `baseline`）
- `方案给人的一句话说明`（string）
- `工艺参数`（object）
- `溯源信息`（object）：`主要参考配方ID`[]、`参考方案类型ID-名称`[]、`参考材料ID-化学式`[]
- `预期结果标签`（object）：`预期晶体尺寸`、`预期风险水平`、`风险来源简述`[]

`工艺参数`：

- `原料信息`、`原料标准化`、`助熔剂信息`、`助熔剂标准化`、`容器`、`籽晶`（string）
- `分离与后处理`（object）：`分离方式`、`分离温度_摄氏`（number）、`晶体的进一步处理`
- `温度程序`（object）：
  - `是否存在次高温预反应段`（"是"/"否"）
  - `低温段保温温度_摄氏`（number）、`低温段保温时间_h`（number）
  - `升温到次高温时间_h`（number）、`次高温段温度_摄氏`（number）、`次高温段保温时间_h`（number）
  - `升温到最高温时间_h`（number）、`最高温段保温温度_摄氏`（number）、`最高温段保温时间_h`（number）
  - `降温速率_主降温_℃每小时`（number）、`降温时间_主降温_h`（number）
  - `冷却速率_至室温_标签`（string，如 `炉冷`）

注意 `℃` 是单个 Unicode 字符（U+2103），不是 `°C` 两个字符。序列化时保持原字符，避免平台侧匹配失败。

## 校验器检查项

ERROR（阻止下发）：

- 方案数组为空 / 元素不是对象
- `方案ID` 缺失或重复
- 缺 `方案类型`、`工艺参数`、`温度程序`
- 最高温不高于低温段或次高温段
- 方案文件不是合法 JSON

WARN（提示，不阻止）：

- 缺 `方案给人的一句话说明`、`溯源信息` 字段、`预期结果标签` 字段
- `原料信息` / `助熔剂信息` / `容器` 等为空
- 声明"无次高温预反应段"但仍填了 `次高温段保温时间_h`
- `降温速率 × 降温时间` 推出的终温与低温段差 >150℃
- 主降温时长 >72h（平台单任务时长上限需与平台确认）
- 次高温低于低温段
- 比例字符串解析不出数值
