# 选题汇报 (L2)

## Goal

把 `problem_modeling` 阶段各 substage 的产出整合成一份**结构化选题汇报文档**，目标是：

> **让导师 3 秒抓核心、3 分钟判方向、不做问答题只做选择题。**

这份文档是 problem_modeling 阶段的**收口产物**——它不产生新研究内容，而是把前面散落的"意图 / 文献 / 空缺 / 问题 / 假说 / 约束"整合成一份可以直接发给导师、当面讲结论、推进选题决策的汇报材料。

---

## 核心方法论：冯唐结构化思维三原则

本 substage 的所有产出都按以下三原则组织，请在产出每个字段时自检：

| 原则 | 含义 | 在本文档的体现 |
|---|---|---|
| **结论先行** | 金字塔顶端先给结论，不铺垫背景、不说废话 | 第一章 100 字内必须给出首选选题 + 沟通诉求 |
| **金线逻辑** | 一根逻辑线贯穿全文，每一节纵向支撑上一级 | 选题 X 的 8 节形成"问题 → 现状 → 方法 → 创新 → 可行性 → 风险"闭环 |
| **MECE 分类** | 互不重叠、完全穷尽 | 横向对比表的维度、风险拆解、待讨论问题分类都要 MECE |

**反面案例**（不许这样写）：
- "近年来，XX 领域发展迅速，受到了广泛关注……" → 结论先行原则违反，删
- "本研究的创新点很多，主要体现在多个方面" → 不 MECE，必须拆到 ≤3 条且每条可验证
- "希望老师指导一下方向" → 给导师留问答题，必须改成"我的初步判断是 X，请确认"

## 工作流（按顺序执行）

### 第 1 步：拉取并核对上游产出

读取上表所有上游文件，做一次"产出完整性"扫描：
- intent 是否给了领域、研究类型、用户目标？
- literature 是否列了 ≥3 篇和核心问题直接相关的结论？
- gap 是否每条都标了置信度，且高置信度空缺 ≥1 条？
- question 是否每条都给了操作化定义？
- hypothesis 是否每条都可证伪？
- constraints（若存在）是否明确了周期上限、资源约束？

任何一项不达标 → 告知用户并询问是否继续。

### 第 2 步：草拟第一章核心结论

**先确定首选选题**，再倒推首选依据。判断首选选题的优先级：

1. **缺口最明确**（高置信度空缺 + 文献支撑）
2. **平台最可复用**（实验室现有基础 ≥ 2 项）
3. **创新最可落地**（核心创新点能用 1 句话说清）
4. **周期最可控**（在 constraints 周期约束内能完成核心实验）

第一章必须 4 要素齐全：**选题数量 + 首选选题 + 首选依据(1-2 条) + 沟通诉求**。

沟通诉求要具体到"需要导师拍板什么"，不要写"请老师指导"。

### 第 3 步：逐题展开第二章 8 节论证

按 spec 模板的 8 节顺序填写，**首选选题放第一位并标 (首选)**。每节填写的核心要点：

| 节 | 关键自检 |
|---|---|
| §1 概念界定 | 2-3 个核心术语，每个标定义出处（文献/标准） |
| §2 核心问题 | 1 句话 + 边界（纳入/排除）+ 追溯 Q-xxx |
| §3 现状与缺口 | 共识 ≤3 条 + 缺口 ≤3 条，每条缺口追溯 G-xxx |
| §4 挑战 | 科学问题固有难度，3 条以内，每条配"为什么难" |
| §5 方法 | 方法直接对应 §2 问题；技术路线 3 步 |
| §6 创新点 | ≤3 点，每点追溯 H-xxx，对应 §3 一条缺口 |
| §7 可行性 | 实验室基础 + 个人积累 + 预实验(可选) |
| §8 风险 | 每个风险配可执行预案，不许只写"有难度" |

**金线自检**：§3 缺口 → §6 创新点 → §7 可行性，必须能串成"我看到了什么缺口、我用什么创新解决、我有什么基础做出来"。串不起来就是逻辑断了，回去补。

### 第 4 步：填第三章横向对比表

MECE 拆维度，按导师决策优先级排序。**必含五类维度**：
- 创新程度（顶刊适配性）
- 实现难度（人力/设备/数据）
- 预计核心研究周期
- 成果产出预期（论文层级/数量）
- 与实验室主方向匹配度 + 个人能力匹配度

每个格子不能空，至少给"高/中/低 + 一句话理由"。

### 第 5 步：填第四章待讨论问题

**这是这份文档的灵魂**——把导师可能问的问题提前列出来，每条都附"我的初步判断"，必要时附"备选方案"。

- **封闭式选择题**：至少 2 条，每条给"我的判断 + 备选方案"
- **开放式问答题**：至少 2 条，每条给"我的初步判断"

封闭式问题示例：选题方向 / 边界调整 / 创新点优先级 / 方法选型 / 时间节点确认。
开放式问题示例：缺口立论是否扎实 / 方法是否最优 / 预实验对照是否充分。

**不许出现**"希望老师给些建议"这种空白问答题——所有问题必须先给答案。

### 第 6 步：填第五章下一步工作计划

3-5 个里程碑节点，每个节点明确"做什么 + 周期"。若 constraints 存在，周期必须与之对齐。

### 第 7 步：跑验收清单

按 spec 文档末尾的"验收标准"自检 10 项，任何一项不达标回去补。

## 汇报使用技巧（写给学生的元指导，**不写入产物文档**）

在交付产物后，附上一段简短的汇报建议给用户（不写入 `topic-briefing.md` 文件，仅在对话中告知）：

1. **提前发文档，当面讲结论**：提前 1-2 天把文档发给导师预判，当面沟通开口直接讲"核心结论 + 待讨论问题"，导师不问就不逐字念细节。
2. **导师提异议时，先接事实再补逻辑**：不要急着反驳，先记录导师观点，再用"文献/预实验事实 + 逻辑推导"补充你的判断（符合金线"事实为基础"）。
3. **控制单文档篇幅**：3 个选题以内，总篇幅不超过 6 页。实质大于形式，不要用冗余格式和废话凑页数。
4. **封闭式问题当头炮**：当面沟通从第四章（一）封闭式选择题开始，先把决策敲定，再讨论开放式问题。
5. **导师签字后再走第五章**：选题方向没确认前不要进实验室做预实验，避免返工。
