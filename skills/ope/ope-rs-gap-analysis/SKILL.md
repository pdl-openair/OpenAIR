# 空缺分析（L3 — OPE）

基于精读后的文献集合做深度空白分析，识别未解问题，评估创新性与可行性。

## Method

采用"分析 → 讨论 → 输出"三阶段模式：每个子任务初步分析完成后，必须用 AskUserQuestion 主动邀请用户挑战，再产出最终结论。

### 子任务 1：识别未解决问题
从精读文献的"局限性"与"未来工作"中系统扫描四个维度：
- **任务层面**：哪些 OPE 场景未覆盖（如连续动作稀疏奖励、长程任务）
- **方法层面**：估计器有哪些缺陷未解决（如 IPS 高方差、DR 在小样本下的偏差）
- **数据层面**：是否缺乏某些类型的基准数据（如非平稳分布、隐私约束数据）
- **评估层面**：评估指标是否全面（如 OPE 评估本身的 ground truth 缺失）

分类为"理论未解"与"工程未解"两类。

### 子任务 2：分析矛盾结果
对比不同文献在相同实验上的结果差异（如相同 OPE 估计器在不同论文报告的 MSE 差一个数量级），从以下角度解释：
- 数据集差异（规模、分布、评估协议）
- 方法实现细节差异（行为策略估计、奖励归一化）
- 评估指标/标准不同
- 随机种子数量与统计显著性

### 子任务 3：评估创新性与可行性
对每个候选研究方向打分：
- 创新性：与 DM/IPS/DR 等已有方法的区分度；incremental vs breakthrough
- 可行性：数据获取难度（1-5）/ 方法复杂度（1-5）/ 计算资源需求（1-5）/ 时间预期
- 潜在风险点
- 综合优先级排序

### 讨论环节策略
对每个子任务的初步结论，主动向用户提问：
- "你认为哪个研究空白最重要？为什么？"
- "这些矛盾结果里，你是否也遇到过？"
- "你觉得哪个方向的可行性被高估了？"

## Input

- 精读后的文献矩阵/综述表（来自 `ope-rs-literature-filter` 的 `proposal/literature.md`）
- 可选：用户已有的初步研究想法

## Output

按 `schemas/ope/specs/analysis.md` 模板产出，使用 Write 工具写入 `proposal/analysis.md`，结构：
- 未解决的研究问题（含讨论记录）
- 矛盾结果分析
- 推荐研究方向（3-5 个，含创新性/可行性评分 + 讨论记录）
- 头脑风暴综合记录
- 下一步行动建议

## Constraints

- 推理驱动而非总结驱动：分析"文献没说什么"，不只罗列"文献说了什么"
- 有观点有立场：敢于判断"这个方向更有价值"，不让用户自己选
- 标注置信度：不确定的判断明确标注"基于有限信息的推测"
- 把用户当专家：AI 分析是辅助，用户反馈是修正
- 结果落盘到 `proposal/analysis.md`
