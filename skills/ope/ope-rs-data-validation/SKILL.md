# 数据验证（L3 — OPE）

整理 OPE 实验数据，验证数据质量，处理异常值，确保结果可重复。

## Method

### Step 1：收集原始数据
从 `execute/experiments/results/` 收集所有结果文件：
- 验证数据完整性（缺失实验数 < 5%）
- 编制数据清单

```markdown
| 实验ID | 数据文件 | 大小 | 状态 |
|--------|---------|------|------|
| exp_001 | metrics/ope_results.csv | 1.2MB | ✅ 完整 |
| exp_002 | metrics/ope_results.csv | - | ❌ 缺失 |
```

元数据记录：实验配置路径、随机种子、执行时间、环境版本（Python、依赖库版本）。

### Step 2：数据规范化
**文件命名规范**：`{exp_id}_{algorithm}_{env}_{seed}_{timestamp}.csv`

**目录结构**（三级）：
```
execute/data/
├── raw/          # 原始数据（只读，禁止修改）
├── processed/    # 清洗后数据
└── backup/       # 备份
```

**格式统一**：
- 列名标准化（如 `algorithm`, `env`, `seed`, `episode`, `estimate`, `ground_truth`, `mse`）
- 单位统一（时间秒、reward 原始量纲）
- 时间戳 ISO 8601

### Step 3：可重复性检验
- **配置一致性**：所有实验使用相同的超参数（除自变量外）
- **种子正确性**：每个实验的种子记录完整且按预期使用
- **数据质量**：NaN/Inf 比例 < 1%、数值在合理范围
- **跨种子分布**：标准差 < 均值的 30%；识别异常偏离的种子

清单：
```markdown
- [ ] 所有实验配置一致
- [ ] 随机种子正确记录
- [ ] 无 NaN/Inf（或 < 1%）
- [ ] 结果在合理范围
- [ ] 跨种子分布合理（std < 30% mean）
```

### Step 4：异常值识别与处理
**检测方法**：
- 统计：Z-score > 3 或 IQR × 1.5
- 领域知识：超出预期（如估计值远超 ground truth 的合理量级）
- 相对比较：与其他种子差异过大

**异常分类**：

| 类型 | 描述 | 处理方式 |
|-----|------|---------|
| 类型 I | 极端但合理（如某种子方差确实大） | 保留但标记 |
| 类型 II | 实验配置错误（如 batch size 错） | 排除/重做 |
| 类型 III | 数据记录错误（如 NaN/截断） | 修正或排除 |

**处理原则**：
- 保留原始数据（raw 只读）
- 记录处理过程与决策
- 提供排除前后的对比分析

### Step 5：生成验证报告
6 个章节：数据概览 / 数据规范化 / 可重复性检验 / 异常值处理 / 清洗后数据 / 下一步行动。

## Input

- 实验执行原始数据（来自 `ope-rs-experiment-execution` 的 `execute/experiments/results/`）
- 可选：数据质量标准、异常判定规则

## Output

按 `schemas/ope/specs/data_validation.md` 模板产出，使用 Write 工具写入 `execute/data/data_validation.md`，结构：
- 数据概览（清单 + 数据量统计）
- 数据规范化（目录结构 + 命名规范）
- 可重复性检验（检验结果 + 问题记录）
- 异常值处理（检测结果 + 处理前后对比）
- 清洗后数据（位置 + 使用说明）
- 下一步行动

## Constraints

- 原始数据不可修改：所有处理基于副本
- 处理过程可追溯：每个异常值记录原因和处理方式
- 可重复：数据清洗过程必须确定性
- 验收门槛：完整性（缺失 < 5%）/ 质量（NaN < 1%，异常 < 10%）/ 可重复性（跨种子 std < 30% mean）/ 文档完整性
- 多轮讨论：用 AskUserQuestion 确认异常处理方式
- 结果落盘到 `execute/data/data_validation.md`
