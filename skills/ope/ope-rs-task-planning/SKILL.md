# 任务规划（L3 — OPE）

将实验设计方案拆解为可执行任务清单，制定研究计划与里程碑。

## Method

### 子任务 1：任务拆解

1. **模块划分**
   - 数据处理模块：D4RL/RecoGym 数据加载、预处理、轨迹切分
   - 算法实现模块：基线 OPE 估计器（DM/IPS/DR/WDR/FQE）、目标方法、对比方法
   - 评估框架模块：指标计算（MSE/Bias/Variance）、统计检验、可视化
   - 实验管理模块：配置管理、随机种子、日志记录

2. **依赖关系梳理**
   - 模块间依赖：数据 → 算法 → 评估 → 可视化
   - 任务间依赖：哪些必须串行，哪些可并行
   - 资源依赖：GPU、存储、数据集获取

3. **子任务定义**
   - 每个子任务有明确输入、输出、验收标准
   - 估计工时：每个 2-8 小时
   - 标记难度：高/中/低

### 子任务 2：计划制定

1. **里程碑设定**（逆推法）
   - 关键节点：代码原型完成 → 首批实验结果 → 完整实验 → 论文初稿
   - 从截止日期往前排
   - 不确定性任务预留 20-30% 缓冲

2. **优先级排序**
   - 核心路径任务优先（影响整体进度）
   - 独立任务优先（可并行推进）
   - 风险任务优先（技术难度高、不确定性大的任务，如新估计器收敛性证明）

3. **资源分配**
   - GPU 时间：按任务需求估算（OPE 评估通常比策略训练轻，但 FQE 类需要训练 Q 网络）
   - 人力分配（团队项目时）
   - 时间分配：每日/每周投入时长

输出表格示例：
```markdown
| 任务ID | 任务描述 | 所属模块 | 依赖 | 工时 | 优先级 |
|-------|---------|---------|------|------|-------|
| T1 | D4RL 数据加载器 | 数据处理 | 无 | 4h | P0 |
| T2 | IPS 估计器实现 | 算法实现 | T1 | 6h | P0 |
```

## Input

- 实验设计方案（来自 `ope-rs-experiment-design` 的 `design/experiment_design.md`）
- 可选：用户已有的任务拆分思路或时间约束

## Output

按 `schemas/ope/specs/task_plan.md` 模板产出，使用 Write 工具写入 `plan/task_plan.md`，结构：
- 模块划分（数据/算法/评估/管理四模块）
- 任务依赖关系（依赖图 + 关键路径）
- 子任务清单（含工时、优先级）
- 里程碑计划（含目标日期、交付物）
- 资源计划（GPU 分配 + 周计划）
- 风险与应对

## Constraints

- 可执行性优先：任务拆解到 2-8 小时粒度，不悬空
- 依赖要清晰：明确串行/并行关系
- 时间要实际：基于用户真实可用时间，不理想的平均预估
- 留有缓冲：不确定性越大的任务缓冲越多
- 多轮讨论：用 AskUserQuestion 与用户确认时间和优先级
- 结果落盘到 `plan/task_plan.md`
