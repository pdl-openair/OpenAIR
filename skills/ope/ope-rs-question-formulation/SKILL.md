# 问题建模（L3 — OPE）

将模糊的研究想法凝练成具体、可验证的研究问题，并展开多角度头脑风暴。

## Method

### 子任务 1：研究问题提出
1. 读取 `proposal/analysis.md` 的未解决问题清单
2. 每个空白按"重要性 × 可操作性"排序
3. 应用 **SMART** 原则将空白转化为研究问题：
   - **S**pecific（具体）：指向明确的估计器/场景/现象
   - **M**easurable（可测量）：有明确指标（MSE/Bias/Variance/样本效率等）
   - **A**chievable（可实现）：在现有数据与算力下可完成
   - **R**elevant（相关）：对 OPE 领域有实质贡献
   - **T**ime-bound（有时限）：有明确的完成时间预期

每个 RQ 输出格式：
```markdown
## RQ1: [问题陈述]
- 对应研究空白：[来自 analysis.md]
- Motivation：为什么重要
- 初步假设：预期会发现什么
- 验证方式：实验/分析/模拟
- 所需资源：数据、算力、时间预估
- 潜在挑战
- 优先级：高/中/低
```

建议输出 3-5 个 RQ，按优先级排序。

### 子任务 2：头脑风暴与讨论
对每个 RQ 从五个角度评估：

1. **技术可行性**：方法是否能实现？现有工具/代码库是否支持？算力是否够？
2. **数据可用性**：D4RL/RecoGym/自采数据是否够？质量是否足？
3. **研究创新性**：与 DM/IPS/DR 等已有方法的差异；incremental 还是 breakthrough
4. **潜在风险**：实验失败的最坏情况？结果不符预期怎么办？
5. **研究影响力**：能发表在什么 venue？对领域的实质推动？

输出含风险矩阵：
```markdown
| 风险类别 | 可能性 | 影响程度 | 应对方案 |
|---------|--------|---------|---------|
| 估计器不收敛 | 中 | 高 | 准备 fallback 到 DR 基线 |
```

## Input

- 研究空白分析（来自 `ope-rs-gap-analysis` 的 `proposal/analysis.md`）
- 可选：用户已有的初步想法

## Output

按 `schemas/ope/specs/question.md` 模板产出，使用 Write 工具写入 `proposal/question.md`，结构：
- 研究问题清单（3-5 个 RQ，含详细描述）
- 头脑风暴记录（每个 RQ 的五角度分析）
- 推荐优先级与排序理由
- 下一步行动计划

## Constraints

- 先窄后宽：从一个小而具体的 OPE 问题开始，不要一开始就做大而泛的问题
- 有观点有立场：敢于判断"这个问题更有价值"
- 可操作性第一：每个 RQ 必须有明确验证路径
- 多轮对话：用户想法模糊时先提问细化，不替用户做决定
- 诚实地指出明显不可行的想法并给替代建议
- 结果落盘到 `proposal/question.md`
