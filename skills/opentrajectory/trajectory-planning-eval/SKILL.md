# 轨迹规划评估

帮助研究者在多个候选轨迹或方案之间做出有依据的选择：明确评估维度、逐候选分析、给出推荐与后续行动。

## Do NOT use when

- 只有单一方案需要评估（无对比对象）。
- 用户需要的是定量优化（有明确目标函数），应使用优化类工具。
- 用户只是询问某个方案的原理或背景，不需要做选择。

## 执行流程

### 第一步：澄清评估目标

如果用户描述不完整，先确认以下信息再继续：
- **研究目标**：想解决什么问题，最终决策是什么
- **候选方案**：有哪些轨迹/策略，各自的关键参数或特征
- **约束条件**：时间、资源、物理/化学约束、必须满足的硬性要求

若缺少候选方案描述，必须追问后再继续；若缺少约束条件但候选描述完整，可直接进入第二步并在输出中标注约束未指定。信息足够时直接进入第二步，不要过度追问。

### 第二步：建立评估维度

根据研究目标选择 3-5 个最相关的维度，遵循以下原则：
- 优先选择与用户明确约束直接相关的维度
- 若用户未指定约束，从稳定性、成本、可复现性中至少选 2 个作为基础维度
- 所有维度必须对所有候选均可评价，不选只适用于部分候选的维度

常用维度示例：稳定性（能量漂移、收敛性）、覆盖度（构象空间、参数空间探索）、约束满足度（是否违反硬性限制）、计算/实验成本、可复现性与可验证性。

为每个候选在每个维度上给出定性评价或相对评分，说明判断依据。

### 第三步：汇总与建议

- 给出推荐排序，明确首选方案及理由
- 指出主要 trade-off（哪个候选在哪个维度上有优势但在哪个维度上有代价）
- 提出 1-3 条可执行的后续验证实验或补充采样建议

## 输出结构

评估结果应包含：
- **总结**：一段话说明推荐结论和核心理由
- **候选对比表**：各候选 × 各维度的评价矩阵（Markdown 表格）
- **推荐排序**：从优到劣，附简短说明
- **后续行动**：具体可执行的下一步

若本 skill 作为 pipeline 中间节点使用，同时输出结构化 JSON：`{ candidates[], dimensions[], matrix[][], recommendation_order[], next_steps[] }`。

如果信息不足以完成评估，说明缺少哪些关键信息，以及补充后能得出什么结论。

输出必须包含 `status` 字段（`"completed"` / `"failed"` / `"partial"`），符合 `output.schema.json`。参考 `examples/request.json` 与 `tests/replay.md`。
