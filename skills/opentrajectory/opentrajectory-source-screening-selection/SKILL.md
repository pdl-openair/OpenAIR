# 文献筛选与优选

## 目标

从 Node5 的真实候选文献中选出**当前值得继续深读**的文献，并给出简洁、可追溯的科研理由。

只依据当前可见的研究问题、研究上下文、标题、摘要和 EvidenceSchema（如有）；不要补造未出现的实验、结果、机制或适用条件。

## 科研判断

对每个候选给出一个判断：

- `priority`：直接回答核心问题、补足关键比较/机制/边界证据，或提供可能改变当前结论的重要冲突/负证据，当前应优先深读。
- `supporting`：不能直接回答核心问题，但能为本轮判断提供**明确且当前需要的实际证据支撑**，值得本轮继续深读。
- `defer`：可能有价值，但当前信息不足、决策价值较低，或主要提供宽泛背景而不会明显改变本轮证据判断。
- `exclude`：当前可见内容已经足以确认与研究问题及关键证据需求没有实际科研关系。

不要因为摘要缺失、无法访问、没有 PDF、来源不熟悉而直接 `exclude`。访问难度与科研价值分开判断。

## 关键边界

- 标题与摘要冲突时，以摘要揭示的实际研究内容为准。
- 摘要缺失时，只使用标题能够支持的有限信号；标题与核心问题高度具体匹配时可保留为 `priority`、`supporting` 或 `defer`，理由中说明依据仅来自标题，不推断未见事实。
- 负结果或冲突证据只要直接检验核心判断并可能改变结论，就不能因“不支持预期”而降级。
- 研究问题要求具体机制、直接比较或条件边界时，直接测量/直接比较的原始研究通常优先于只提供宽泛背景的综述；宽泛综述若本轮没有实际证据增量，使用 `defer`。
- EvidenceSchema 只辅助识别已定义证据目标，不替代完整研究问题。仅在标题或摘要明确涉及对应目标时填写 `relevant_target_ids`；Schema 缺失或只覆盖部分问题时正常筛选，不强行映射，也不因无法映射而降级核心文献。

## 排序与输出

对每个 `priority` 和 `supporting` 候选给出 `reading_priority`（1–100），表示**当前本轮继续深读的科研优先度**；数值越高，越应优先深读。这个数值是你的科研判断，不是代码评分。判断依据只包括：对核心问题的直接程度、可能改变当前判断的程度、以及当前标题/摘要对该价值的支持强度。`defer`、`exclude` 使用 `null`。不要按访问便利、期刊名气或年份给优先度。

优先度使用稳定的绝对含义，便于不同候选组之间比较：90–100 表示直接且高判别价值，70–89 表示明确值得优先深读，40–69 表示有实际支撑价值但优先度较低，1–39 仅用于仍值得本轮深读但价值有限的候选。不要为了拉开差距机械使用满量程。

每个候选都输出一条 `judgment`。每条 `reason` 只写一条具体科研依据，不复述标题，不使用空泛评价，不把未知事实写成已知结果。

`evidence_roles` 和 `relevant_target_ids` 只在能增加下游判断价值时填写，不为凑字段强行标注。

模型只输出候选 ID 和科研判断，不重新填写 DOI、标题、作者、链接、来源或 provenance。

## 代码负责

代码负责候选身份绑定、原始事实与 provenance 保留、按模型给出的 `decision + reading_priority` 做确定性全局排序并生成正式 `priority_rank`、未评估记录和下游兼容结构；代码不重新解释或重算科研优先度，也不决定固定入选篇数。
