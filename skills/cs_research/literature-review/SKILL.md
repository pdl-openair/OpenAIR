# 关键文献定位与文献调研

## When to use

Use this skill when:
- 用户只有题目、关键词、导师给的综述或少量种子论文，需要先知道怎么搜、先读什么、争议在哪里。
- 需要形成检索词簇、数据库/来源入口、候选论文分层、阅读优先级和主要争议点。
- 需要为后续证据抽取或机制分析准备来源包，但还没有足够材料直接下结论。

Do NOT use this skill when:
- 用户要求抽取某篇论文的证据条目；应转到 evidence-mining。
- 用户要求把已有证据串成机制链；应转到 causal-reasoning。
- 用户只给出“找文献/做综述”但没有研究对象、领域范围或种子线索；先要求补充，不创建空产物。

## Input

用户需提供研究主题或问题。优先补充：

- 已有关键词、中文/英文同义词、缩写。
- 种子论文、综述、DOI、arXiv、PMID 或导师给的阅读清单。
- 学科边界、时间范围、材料/模型/任务限定、排除条件。
- 期望输出：检索词、必读论文、争议点、阅读顺序或候选来源表。

## DOI / Source ID rule

- 所有候选论文、代表论文、必读论文、争议点关键论文和阅读顺序条目，都必须保留可追溯标识：优先 DOI，其次 URL、arXiv、PMID、PMCID、OpenAlex 或 Semantic Scholar ID。
- 如果用户输入、题录、检索结果或上下文中出现 DOI / URL / arXiv / PMID，不得在总结、表格或人话摘要中省略。
- 如果当前没有拿到 DOI，不要编造；在 DOI / ID 列写 `待补 DOI`，并在“来源状态、缺口和下一步补证据清单”中列为待核验项。
- 任何总结 agent 或二次改写都必须保留 DOI / URL / arXiv / PMID；压缩内容时可以删解释，不能删来源 ID。

## Steps

### 1. 界定检索边界

确认研究对象、核心问题、时间范围、来源范围、排除条件和第一轮阅读目标。

如果信息不足，只输出“待补输入”，不要编造论文或声称已经检索。

### 2. 生成检索词簇

整理：

- 核心概念词：对象、材料/模型、方法、现象、指标。
- 同义词/缩写/英文翻译。
- 排除词和边界词。
- 3-6 条第一轮检索式，每条说明用途。

### 3. 候选论文分层

若已有真实来源，按来源信息分层；若没有真实来源，只给筛选框架和待检索候选类型，不输出虚构标题。

```markdown
| 层级 | 论文/来源 | DOI / URL / ID | 为什么先看 | 来源状态 | 需要人工复核 |
|---|---|---|---|---|---|
| 入口综述 | ... | 10.xxxx/xxxxx 或 待补 DOI | 建立领域边界 | 用户提供/题录/摘要/全文 | ... |
| 代表工作 | ... | 10.xxxx/xxxxx 或 arXiv:xxxx.xxxxx | 方法或体系绕不开 | ... | ... |
| 争议/负结果 | ... | URL/PMID/OpenAlex 或 待补 DOI | 帮助识别分歧 | ... | ... |
```

来源状态必须区分：用户提供、题录、摘要、可读全文、外部检索失败。

### 4. 主要争议点和阅读顺序

输出第一轮阅读路径：

- 先读什么：综述/方法基础/代表实验/评测基准。
- 带着什么问题读：每类论文要确认的证据点。
- 主要争议点：只写“待核验争议”，不写成结论。
- 下一步补证据：需要 DOI、全文、数据、实验记录或专家确认的地方。

## Output

写入当前任务工作区的 `proposal/literature.md`。报告包含：

1. **研究对象与检索边界**
2. **检索词簇与检索式**
3. **候选论文分层与必读理由**
4. **主要争议点和阅读顺序**
5. **来源状态、缺口和下一步补证据清单**

## Failure handling

- 用户未提供研究对象或范围 → 返回待补输入，不创建候选论文结论。
- 无法访问外部检索源 → 只输出检索策略、来源入口和缺口，不声称已完成检索。
- 只有题录/摘要 → 只能作为候选和阅读优先级，不能作为证据结论。
