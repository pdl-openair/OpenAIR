# `structured-requirement-generation` Rubric

## 1. 评分尺度

| 分数 | 含义 |
| ---: | --- |
| 4 | 完全满足，可直接供 Phase2 使用 |
| 3 | 基本满足，仅有轻微缺陷 |
| 2 | 部分满足，需要明显人工修正 |
| 1 | 明显不满足，需求理解不可靠 |
| 0 | 不可接受，或触发硬门禁 |

## 2. 评分维度

| 维度 | 权重 | 4 分标准 | 0 分 / 硬性拒绝 |
| --- | ---: | --- | --- |
| 需求忠实度 | 35% | 完整保留明确事实，不做解释性扩展 | 发明信息或丢失核心对象 |
| 对象、指标与边界拆分 | 25% | 字段分工清楚，可直接供 Phase2 使用 | 关键字段混写导致下游无法使用 |
| 缺口与置信度 | 20% | 歧义显式记录，置信度与完整度一致 | 低置信无缺口，或把歧义写成事实 |
| 意图与来源范围 | 15% | 意图和明确来源偏好识别准确 | 静默丢失明确比较、决策或来源限制 |
| 紧凑性 | 5% | 输出短而可用 | 输出 query、方案或长段解释 |

## 3. 人工复核重点

忠实度优先于丰富度；重点检查无依据补全、比较关系、数值条件、来源范围和职责越界。

## 4. Judge 限制

Judge 必须给出分项得分、证据片段、扣分点、硬门禁命中、置信度和人工复核建议。Judge 不得覆盖硬门禁。
