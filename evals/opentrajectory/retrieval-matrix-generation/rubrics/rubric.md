# `retrieval-matrix-generation` Rubric

## 1. 评分尺度

| 分数 | 含义 |
| ---: | --- |
| 4 | 完全满足，可直接供召回执行器使用 |
| 3 | 基本满足，仅有轻微缺陷 |
| 2 | 部分满足，需要明显人工修正 |
| 1 | 明显不满足，检索策略不可靠 |
| 0 | 不可接受，或触发硬门禁 |

## 2. 先判硬门禁

以下问题不得仅通过低分处理，必须判失败：query 不可执行、明显重复凑数、对象覆盖不平衡、必要 pairwise 完全缺失、全对象机械 hard AND、来源策略丢失、风险误转 strict / NOT、低价值 fallback 掩盖失败。

## 3. 评分维度

| 维度 | 权重 | 4 分标准 | 0 分 / 硬性拒绝 |
| --- | ---: | --- | --- |
| Query 可执行性与差异化价值 | 25% | 英文、布尔正确、去重，每个 query 有明确召回目的 | 不可执行、明显重复或主要靠凑数 |
| 对象覆盖与比较完整性 | 30% | 多对象平衡，具备 per-object 与必要 pairwise | 单对象偏置、全对象 hard AND 或必要 pairwise 完全缺失 |
| 约束策略化与可追溯性 | 20% | 时间、语言、来源质量和排噪均结构化利用 | 明确约束丢失，或只塞进 query 文本假装使用 |
| 忠实度与探索边界 | 15% | 核心、宽泛与探索层级清楚，不发明硬条件 | 风险、候选值或推测进入 strict / must-have / NOT |
| 降级诚实性 | 10% | 不足、fallback 与人工复核状态透明 | fallback 掩盖失败，或拒绝样例被包装成通过 |

## 4. 人工复核重点

比较任务逐项核对对象入口、pairwise、对象平衡和 hard AND；降级任务核对 fallback 是否有价值、是否正确进入人工复核或拒绝。

## 5. Judge 限制

Judge 必须给出分项得分、证据片段、扣分点、硬门禁命中、置信度和人工复核建议。Judge 不得覆盖硬门禁。
