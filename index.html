Why OpenAIR

科研的四个老问题，闭环的四个新答案#

OpenAIR 把「科研怎么做」建模为可编排、可验证、可追溯的四阶段过程模型，而非一条写死的流水线

痛点周期长、工具分散：文献、计算、实验、写作各在一套工具里，人在中间当「胶水」
可编排四阶段过程模型统一编排；skill 承载能力、registry 统一调度，长程任务持续执行
痛点结果难复现：换个人、换台机器，流程跑不出来，谁也说不清哪步出了偏差
可验证skill 以 SKILL.md + 输入输出契约定义，可独立测试、可回放（replay 模式零密钥复现全流程）
痛点证据难追溯：结论出自哪个输入、哪个版本、哪次计算，事后无从核验
可追溯每步产物的来源链全程可回看——哪个 skill、什么输入、什么版本，形成可信证据链
痛点反馈利用不足：实验结果回来了，却难回流到下一轮设计与决策
闭环迭代干实验（计算验证）与湿实验（制备反馈）在同一闭环内回注迭代，持续逼近科学发现

Mechanisms

四层机制：从约束执行到证据复核#

直面科研智能体从演示走向可复用应用的三类工程挑战——执行难约束 · 反馈难闭环 · 过程难复核

🔁 四阶段任务编排

problem_modeling → solution_design → execution_validation → insight_generation，支持阶段状态管理与检查点回退；L2 通用编排与 L3 领域原子 Skill 分层，结构化输入输出约束与契约测试落实到每次能力调用——保留编排灵活性，同时提高执行可控性。

🧩 契约化 Skill 管理

按标准化 frontmatter、目录结构与 Schema 组织 200+ 多领域技能，支持注册、检索、组合、版本管理与契约测试；新领域即新增 skill 包、平台无需改代码，replay 回放可零密钥复现同一执行过程。

🧾 分层证据追溯

记录 Skill 来源、许可证、阶段映射与迁移记录，并关联任务执行与数据产物；追溯链从来源与版本逐步扩展到计算参数、实验数据、运行环境与结论验证依据，支撑过程审查与复现。

🧪 干湿实验反馈衔接

适配云际计算平台与云实验平台，实测数据回传后直接进入下一轮方案修订与任务编排，支持基于反馈的阶段回退与迭代；反馈驱动的自动策略学习列为后续研发方向。

Quick Start

三种方式开始#

A · 零安装
在线演示浏览器直接打开完整工作台快照，免登录只读。
B · 本地零密钥
openair CLIpipx install openair-cli && openair up，约 10 分钟得到本地实例与 replay 回放。
C · 完整能力
Docker 手动部署git clone + docker compose up，配置模型网关与外部账号进入 live 模式。
# 方式 B：openair CLI
pipx install openair-cli
openair up            # 克隆 → 配置（随机密钥+管理员）→ 启动 → 打开浏览器

# 方式 C：Docker
git clone https://github.com/pdl-openair/OpenAIR.git
cd OpenAIR && cp .env.example .env
docker compose up -d --build
# 工作台 http://localhost:8080 · API http://localhost:8000/health
