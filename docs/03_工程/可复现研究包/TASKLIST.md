## 1. 当前阶段用户结果与完成条件

贡献者能从已有真实研究中，以可接受的新增人工成本形成并确认一份可追溯研究包；接手者无需读 YAML 或依赖原作者解释，就能理解研究对象、条件、结果性质、验证边界和来源位置，判断哪些内容可采用、需调整或需重新核验，并在 OpenAIR 中继续新的真实研究。

用户最终能完成：**形成 → 确认发布 → 分享 → 导入 → 理解 → 选择采用 → 确认当前研究方案 → 继续研究 → 回溯依据**。

收益是减少理解、查找和恢复研究起点的重复工作。是否重跑原研究由当前可信度需要决定，不强制所有使用者先复现一次。

本轮以公开SimCSE成果贯穿：贡献者通过产品入口形成并确认；另一普通测试身份能够接收、阅读和核查来源，采用到自己的研究方案，经正式检查与用户确认，完成必要后续研究或有依据的无需继续判断，并回溯采用内容。既有内容存储、规划和执行机制优先复用。

**演示通过的最低条件：** 固定候选版本在明确的演示环境中运行真实前端、后端、数据库与存储；上述流程通过产品入口连续完成，不靠终端拼包或口头补步骤。展示结果、来源、限制、确认边界及错误恢复；关键操作实际留证、重跑成立。演示身份与分享权限真实有效，科研结果不以fixture或回放冒充。用户实际核查效果后，才标记本轮“可用、可演示”。

**本轮后置：** 原冻结的P1/P3效率对照与真人排期、异形第二案、正式生产上线与普通用户开放。保留原冻结记录及全部正式合同，不删除要求、不声称已经完成正式Product Done；效率测量以后仍按事前口径执行。真实首案形成时尽量保留操作记录，演示不冒充受控效率测量，也不把演示后已熟悉内容的人当首次接手者。

### T3｜从真实成果形成并确认 Package

- **目标／贡献：** 贡献者少量补充关键科研语义即可形成可复用起点，无需重录整个研究。
- **事实基线：** T2资产基础已验证；T3 Revision 2设计已接收，5接口/确认继承/恢复及S1—S10已明确。RP-3-C1代码规格READY，功能尚未实施，不将确定性代码冒充科研判断。已有确认按精确范围复用，用户只处理必要增量与贡献范围。
- **依赖：** T0、T2。
- **范围／边界：** 从已有成果复用身份、来源、资源和结果；科研对象划分、验证强度和适用边界由具备正式能力的 Agent/Skill 判断；代码只作确定性组装与校验。草稿与发布明确区分，允许贡献者检查、补充并确认。不因缺某个可选资源强制创建工作流或重新实验。
- **Done：** 通过产品入口从首案成果形成合法 v3 草稿，贡献者可核查来源和限制并确认发布；记录系统复用内容与新增人工操作，保留后续 P1 比较数据；未确认/结构非法内容不能伪装成正式发布。
- **停止条件：** 必须大规模重新录入才可形成；来源或科研语义无法可靠确认；达到可信边界时保存已有草稿并指出必要缺口。

### T4｜分享、导入与独立理解

- **目标／贡献：** 新使用者能看懂并决定如何使用，减少向原作者追问和重新查找。
- **事实基线：** 后端导入导出已存在，完整客户端操作与专用可读视图未证明。
- **依赖：** T2、T3。
- **范围／边界：** 提供形成结果入口、符合现有权限的分享/导出方式和另一用户导入路径。视图优先展示问题、验证对象与条件、结果性质、依据和具体位置、资源版本、保持/调整/重新核验边界。具体分享实现由现有基础决定，不预设必须建公开市场。
- **Done：** 接手者通过 UI 完成接收、导入、查看和来源核查；不读 YAML 能完成 P2 所列理解任务；明确区分事实、推断、冲突与未知，系统错误不暴露为操作要求。后台更新不打断阅读，失败不覆盖已可读成果；关键浏览器路径有测试证据。
- **停止条件：** 关键含义只能靠作者口头解释或机器文档获得；分享权限不成立；内容呈现把历史验证误写成当前验证。

### T5｜采用 Package 进入正式规划

- **目标／贡献：** 用户结合当前问题与条件采用可信起点，形成自己的方案。
- **事实基线：** 已有 `planningSources` 与采用分类追溯，但 v3 投影缺对象和验证边界；前端选择入口未证明。
- **依赖：** T1、T2、T4。
- **范围／边界：** 复用正式规划链，补 v3 对象/条件/结果/验证语义和结果级来源，允许选择准确版本及部分采用；处理不同当前条件和多来源冲突。沿用既有来源追溯，不新建 Package 执行权。
- **Done：** UI 选择后，Package 与当前上下文共同进入草案→正式检查→用户确认；已采用、不采用、需重新核验内容可追溯到精确身份/版本/内容；当前条件差异和冲突得到有依据处理；未确认方案不执行，导入不自动产生 Evidence/ScientificState。新版本不静默改写已确认方案；自动化、持久化和产品路径均有本轮证据。
- **停止条件：** 需要绕过正式检查或用户确认；采用分类丢失科研上下文；不能定位真实采用内容。

### T6｜继续研究、资源核验与失败恢复

- **目标／贡献：** 采用后能开展新研究，用户得到可信结果、风险和可执行下一步。
- **事实基线：** 正式执行机制已存在，Package 到执行/资源/最终回溯的完整真实证据未取得。
- **依赖：** T5。
- **范围／边界：** 验证并只修补 ExecutionDecision→WorkUnit→Result→接受/科研状态→完成判断既有链路；原研究资源、当前计划资源和实际使用资源分别留证。需要重新核验时真实执行，不需要时记录依据。合法资产的局部来源/资源/模型失败隔离处理，结构非法资产整体拒绝正式使用。
- **Done：** 至少一项新的真实研究工作，或有依据的“不需继续”判断；结果能回溯采用版本和来源；关键资源实际使用可核查；局部失败保留可信资产、已有结果和阅读状态，重试不重复建立正式事实；不可继续时给出明确影响与下一步。有真实执行与代表性失败恢复测试证据。
- **停止条件：** 需要用 fixture 冒充真实结果；无法确认实际使用资源且影响可信度；继续会形成错误正式结论。

### T7｜完整首案产品演示验收（本轮完成出口）

- **目标／贡献：** 用户实际看见并操作可复现研究包功能，完整流程在产品中可用、可解释、可回溯。
- **事实基线：** 只有源码、协议测试和准备环境证据，没有完整SimCSE产品演示Done。
- **依赖：** T0、T3—T6；消费已验收的T1/T2。
- **范围／边界：** 固定演示环境/版本/两普通测试身份，以真实公开SimCSE资料走形成→确认→分享/导入→理解→采用→正式方案检查与确认→必要继续研究→回溯。仅复用并修补阻断这条链的机制，不引入公开市场、全部领域支持或生产部署。
- **Done：** 上述流程实际通过浏览器连续完成，核心字段与来源/版本保真、权限真实有效、未确认不执行、导入不自动变当前科研事实；结果与必要后续动作可信可核查。记录提交、环境、输入、各步操作/结果、所需运行资源与已知限制；在同条件重跑核心路径，关键受控失败不丢已保存成果。提供可执行演示入口与操作脚本/说明，由用户核查效果并接受。本轮不以效率提升百分比、异形第二案或线上开放作为Done条件。
- **停止条件：** 需要手工改库/终端拼包绕过产品入口才能演示；以fixture冒充科研成果；权限、确认或回溯边界被绕过；关键环节未实跑。发现缺口归属T2—T6回修，不只改验收口径。

### T7-VALUE｜正式首案产品收益验收（后续保留）

- **目标／贡献：** 证明贡献成本可接受、接手者独立理解、重复工作减少且起点可信。
- **事实基线：** 只有工程 fixture，没有真实完整首案 Done。
- **依赖：** T0、T3—T6。
- **范围／边界：** 按事前基线让贡献者与未参与原研究的目标使用者完成真实产品路径，记录人工工作、理解任务、来源核查和继续研究结果；不倒推比较标准，不把模型自评当作独立用户理解证据。
- **Done：** 同一个首案 P1—P5、E1—E6 全部有可核查证据并通过；达到 T0 冻结的产品价值标准；关键接口、组件、数据库和浏览器检查通过。新研究是否科学成功不作为通过前提，但必须是真实工作或可信判断。
- **停止条件：** 产品收益未达到事前标准，或任一 P/E 项未验证；将缺口归属到对应实现任务，不能仅改验收口径。

### T8｜异形第二案通用性验证（后续保留）

- **目标／贡献：** 能力服务另一种研究形态，排除首案特判。
- **事实基线：** 尚无第二案验收证据。
- **依赖：** T7-VALUE；不阻塞本轮T7演示出口。
- **范围／边界：** 选择明显不同的真实研究形态，使用同一协议、产品入口、来源追溯和规划/执行边界；不强制重复首案全部效率对照。
- **Done：** 第二案真实完成形成、迁移、理解、采用及必要后续研究验证，关键对象/条件/结果/来源保真；无领域专用核心字段或专用旁路；记录适用范围及未验证范围，相关回归通过。
- **停止条件：** 仅复制首案换名称；必须新增领域特判才成立；发现核心协议缺口则回到正式设计处理。

### T9｜发布与用户开放验证（后续保留）

- **目标／贡献：** 普通目标用户在实际部署中能稳定使用已验收能力。
- **事实基线：** 当前尚未达 Product Done/Engineering Done，也无线上可用证据。
- **依赖：** T7-VALUE、T8；不阻塞本轮T7演示出口。
- **范围／边界：** 按项目现有发布流程合入、部署、验证数据库迁移与旧资产读取；完成普通账号权限、入口、真实存储、模型和关键资源配置检查；准备失败诊断、恢复/回退方案与可用范围说明。实际发布按该环境已有授权执行，清单本身不是部署记录。
- **Done：** 影响范围内测试与项目要求门禁通过；首案和第二案证据完整；正式环境普通账号可完成关键路径，版本升级后既有包仍可读取；无阻断用户操作或误导科研判断的问题；记录部署版本、线上检查、用户可达入口、支持范围及回退办法。仅“发布准备就绪”不能标记“已开放”。
- **停止条件：** 仅本地通过、关键运行依赖或权限未验证、部署未完成、线上路径失败，或尚有阻断用户结果的问题。

## 5. 测试证据与收口

证据按 Task 关联生产目标、源码提交、执行环境、输入来源、测试/操作记录、结果及未验证事项；详细记录进入相应施工验证账本，TASKLIST 只保存判定与入口。

1. **Task Done：** 本项 Done 满足；关键测试有实际执行证据。未配置依赖、skip、fixture-only 或历史运行不能替代当前要求。
2. **本轮演示阶段Done：** T0—T6与T7演示出口满足、用户核查接受；只声明“在指定演示环境可用、可演示”，附支持范围及真实限制。管理完成度达到100%仅指此阶段。
3. **长期路线/正式产品Done：** T7-VALUE、T8、T9等后续要求按原正式验收合同成立，不能用本轮演示验收代替科研收益、通用性或线上开放。

产品第一原则在验收中的具体落点：

| 原则                                   | 必须取得的结果或证据                                         |
| -------------------------------------- | ------------------------------------------------------------ |
| 从用户结果出发、优先高决策价值信息     | T0 公平基线，T3/T4 优先保留会影响复用判断的内容，T7 真实收益 |

## 6. 更新与非阻塞事项

- 同一根因的新问题进入当前 Task；其他问题进入对应后续 Task。改变协议、产品方向或路线依赖时重新核对正式依据。
- 只有新直接反证才能重开已完成 Task；新提交不自动撤销或继承旧验收。完成一项后更新证据入口并确定下一 CURRENT。
- 首轮不默认增加公开市场、推荐排名、统一科研认证、所有领域覆盖、所有原研究强制重跑等范围。必要性由真实用户目标与新证据决定。
- 当前未完成原因：T0及T1/T2技术已收口；当前T3形成/草稿/确认接口准备，之后T4分享理解、T5采用规划、T6必要继续研究、T7完整演示。主环境未合入，high人审待完成；产品链仍未实跑，不能提前Done。真实首案科研确认由贡献者在T3完成，正式收益/第二案/上线仍后置。
