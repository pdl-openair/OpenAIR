# 05｜Research Package 施工合同

> 状态：v0.3 定稿  
> 日期：2026-09-28

施工只补 Research Package 独有缺口。现有 OpenAIR 能力已经满足正式设计时，直接复用。

## 1. 施工原则

1. **复用现有核心机制。** Package 使用现有 ResearchDesign、ScientificState、Evidence、ExecutionDecision、WorkUnit、资源核验和完成判断机制，不建立平行体系。
2. **科研判断与确定性处理分开。** 需要科研理解、比较、解释或判断不确定性的内容，由具备相应科研判断能力的 Agent / Skill 负责；代码处理身份、版本、引用、结构组装和确定性校验。
3. **只实现 Package 独有能力。** 首轮重点是资产生命周期、协议校验、人类可读呈现、规划来源接入和真实验收证据，不因单个案例重建已有基础设施。
4. **产品价值作为完成依据。** 施工批次可以用测试证明工程行为，但最终完成仍按 [04｜Research Package 验收合同](../../02_产品与Workflow/可复现研究包/04_验收合同.md) 分别判断 Product Done 和 Engineering Done。

## 2. Package 资产生命周期

实现 `spec_version: "3"` Package 的创建、校验、保存、读取、版本化、导出、分享、导入和再次读取。

整个往返过程中保持 Package 身份、版本、来源关系和关键科研语义一致。已发布的 `id + version` 不可原地修改；内容变化产生新版本。

存储优先复用现有资产、文件或 Artifact 基础设施。

按 [03｜Research Package 协议](../../02_产品与Workflow/可复现研究包/03_协议.md) 的兼容规则保留 v2 原文、哈希及旧版本读取/导入/导出。新贡献路径形成 v3；旧包新采用按真实提供内容及其限制进入正式规划，不以缺少 v3 字段为由一律要求升级，也不补造这些语义。需要升级时经科研补充和贡献者确认发布新的内容版本，旧发布版本及历史采用记录保持不变。

## 3. 形成与查看 Package

从已有研究形成 Package 时，必须按 [03｜Research Package 协议](../../02_产品与Workflow/可复现研究包/03_协议.md) 保持参考实例的研究对象、共同条件、验证依据和边界，以及结果级科研性质、来源位置和必要限制。需要科研理解的内容由具备相应资格的 Agent / Skill 形成；代码只恢复和保持能够确定性得到的身份、版本、引用和结构。

产品查看面按 [01｜Research Package 产品与使用设计](../../02_产品与Workflow/可复现研究包/01_产品与使用设计.md) 的顺序优先呈现：

`解决什么问题 → 原研究验证过什么 → 对象与条件 → 关键结果及来源位置 → 可复用资源 → 保持/调整/重新核验边界`

用户无需直接阅读 YAML 才能获得这些核心信息。

## 4. 接入当前研究

施工必须保持 [02｜Research Package 架构设计](../../02_产品与Workflow/可复现研究包/02_架构设计.md) 中“Package 怎样进入新项目”一节定义的规划接入关系。具体实现只补两项 Package 独有责任：

- 使用现有规划来源或追溯关系记录 Package 身份、版本、实际采用内容和需要重新核验的内容；
- ResearchDesign 确认后不建立 Package 特殊执行通道，后续继续走既有 ExecutionDecision、WorkUnit、结果接受和完成判断机制。

Package 中的能力需求只说明研究能力语义，资源记录保持原研究资源身份。

## 5. 失败处理

### 5.1 Package 协议或结构错误

必需字段缺失、坏引用、不支持协议版本、身份冲突等确定性结构错误，意味着当前文档不能作为合法 Package 进入正式使用。

不得删除错误部分后，把剩余内容继续保存或导入为同一 `id + version` 的合法 Package。原始输入和诊断可以保留用于修复；已发布内容发生变化时产生新版本。

### 5.2 合法 Package 使用中的局部失败

外部资源暂时不可取得、来源当前无法访问、当前项目不采用某个实例或后续研究工作局部失败时，只隔离真实受影响的内容；其他仍可信且合同允许独立使用的内容继续保留。

后续是否继续、重试或改走其他路径，由 OpenAIR 正式研究执行机制根据当前状态决定。

## 6. 禁止的实现捷径

以下做法不符合本合同：

- 导入 Package 后直接写入 ResearchDesign、Evidence 或 ScientificState；
- 把 Package 资源记录写成当前项目已经取得、计划使用或程序已经实际使用；
- 在 Package 中固定 Agent、Skill、Provider 或不可替换执行链；
- 用覆盖顺序解决多 Package 的科研冲突；
- 原地修改已经发布的 Package 版本；
- 为单个案例硬编码核心字段或专用运行旁路；
- 为了让测试通过而降低正式协议、科研语义或验收要求。

## 7. 每批施工交付

每一批施工至少交付：

- 修改后的正式代码；
- 对应的确定性测试或真实科研验证；
- 对受影响主链的本轮新证据；
- 当前仍未证明的事项；
- 与 [04｜Research Package 验收合同](../../02_产品与Workflow/可复现研究包/04_验收合同.md) 对应的证据入口。
