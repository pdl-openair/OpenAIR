# 06｜Research Package 最小施工路线图

> 状态：v0.3 定稿  
> 日期：2026-09-28  
> 当前阶段：R2｜最小Package资产闭环；2026-10-09 R1已收口，当前先施工协议保真与兼容基础T1

## 1. 总路线

```text
R0 设计确认（已完成）
→ R1 最新源码适配盘点 + 首案比较基线冻结
→ R2 最小 Package 资产闭环
→ R3 规划接入闭环
→ R4 第一个完整真实案例
→ R5 第二种研究形态验证
→ R6 正式验收收口
```

正式施工一次只推进一个主目标（WIP=1）。每次解决当前主链的第一个真实阻塞；最新代码已经满足某阶段要求时，用证据确认后直接跳过，不重复建设已有能力。

## 2. 阶段与退出条件

| 阶段 | 目标 | 必须交付 | 退出条件 |
|---|---|---|---|
| **R0 设计确认（已完成）** | 确认 v0.3 产品、架构、协议、验收和施工口径 | 已确认的 01—06 | 文档之间无正式职责、协议或验收冲突 |
| **R1 适配盘点 + 比较基线** | 找出执行时最新 `origin/test`（共享集成分支）的首个真实缺口，并在首案形成 Package 前锁定产品价值对照口径 | 最小差距表 + 首案比较基线记录 | 明确已有能力、最小缺口、首案选择、P1/P3 比较口径，只选一个正式施工目标 |
| **R2 资产闭环** | 让一份真实研究形成、保存、导出、导入并可读 | 一份真实 v3 Package + 往返证据 | 身份、版本、来源、对象/条件关系、具体结果位置、验证边界和关键科研语义保持一致 |
| **R3 规划接入** | 让 Package 正确参与当前 ResearchDesign 形成 | 本轮新产生的规划证据 | Package 与当前研究上下文共同进入“草案→检查→用户确认”正式规划链，无直接写入旁路 |
| **R4 首个真实案例** | 证明完整用户链真正产生价值 | 一个完整真实案例 | 该案例满足 [04｜Research Package 验收合同](../../02_产品与Workflow/可复现研究包/04_验收合同.md) 的单案例 Done |
| **R5 第二研究形态** | 排除首案特判 | 第二个明显不同的真实案例 | 同一核心协议、来源追溯、规划接入和正式边界仍成立，无领域专用核心字段或旁路 |
| **R6 正式收口** | 给出首轮产品级完成结论 | 验收记录 + 未验证范围 | 满足首轮 Product Done / Engineering Done，剩余事项不阻塞首轮发布 |

## 3. R1 只读盘点

R1 基于执行时最新 `origin/test` 读取真实实现，不预设新增表、类、API、Skill 或 Service。

只回答：

- 当前是否已有可复用的资产存储、版本、导入导出能力；
- 现有来源追溯能力能否承载 Package 的来源和实际采用关系；
- 正式规划机制是否已有接收可追溯研究资产的入口；
- ResearchDesign 是否需要最小接入，还是现有规划追溯已经足够；
- ExecutionDecision / WorkUnit 是否可以直接消费规划后形成的正式输入；
- 资源实际使用核验是否可以直接复用；
- 哪个真实案例离完整验证最近。

交付一张差距表：

| 能力 | 当前已有 | 最小缺口 | 是否阻塞首个真实案例 |
|---|---|---|---|

## 4. 首案比较基线在 R2 前锁定

为了真实验证“贡献成本低”和“重复工作减少”，首个案例在正式形成 Package 前先记录：

- 不使用 Package 时需要恢复哪些关键事实和步骤；
- 贡献者预计新增哪些人工工作；
- 接手者的公平对照方式；
- 本案例使用哪些可核验指标；
- 哪些真实实验或计算时间不计入人工效率收益。

R2 以后不能用结果倒推或补造这份比较基线。

## 5. 真实案例选择

R4 选择当前正式能力最完整、同时能够暴露 Research Package 核心边界的真实案例，不固定领域。

R5 选择研究形态明显不同的第二案例。例如首案偏真实执行，第二案可以偏证据综合；首案偏证据综合，第二案可以偏真实执行。

第二案例重点证明通用设计能够跨研究形态成立，不要求重复首案全部效率证明，也不允许为了第二案例把领域专用字段写进核心协议。
