# OpenAIR CS 论文复现 Workflow 设计合同

> **状态：定稿**  
> **职责：定义 OpenAIR 中 CS 论文复现 Workflow 的研究骨架、节点职责、科研依赖和交付要求。**  
> 通用对象、能力与执行机制遵循 `docs/01_核心设计/**`。

## 1. 目标与适用范围

CS 论文复现 Workflow 通过稳定的专业研究职责，减少复现目标偏移、实验条件错配和无依据的成功判断，帮助用户完成**真实、可追溯的复现，并明确是否达到约定标准、依据是什么、仍有哪些限制**。

本 Workflow 适用于能够通过程序运行或计算实验检验的论文结果，包括重新训练与评测、发布模型重新评测、算法或系统实验重跑，以及选定实验结论的核验。单纯解释论文、检索资料、调试代码或核查理论证明，按相应研究需要处理。

复现范围以用户选定的结果和研究要求为准。全文实验、某项结果、发布权重评测和小规模试运行支持不同范围的结论。系统保留用户明确的模型变体、监督方式、实验对象和目标条件，不静默扩大或缩减复现范围。

Workflow 固定专业职责和必要依赖。具体论文、实验安排、实现、资源、环境和比较判据由当前项目确定。

## 2. 研究输入与规划

各节点按职责读取正式研究上下文：目标论文及待复现结果、复现方式、已知实验条件、可用资料与历史结果，以及时间、算力、费用、权限和风险边界。已明确的条件继续保留；未知项说明其影响，不重新将已知要求当作未指定。

研究方案（ResearchDesign）应明确本项目要验证什么、通过哪些研究工作获得答案、以什么要求判断完成，以及必要依赖和可复用成果。用户要求真实复现时，方案必须覆盖从基线与实验设计到真实执行、结果比较和复现结论的完整责任。只交付执行方案，属于方案设计范围。

参考数值、具体版本或执行配置尚未取得时，将相应获取与核验工作纳入方案。资料不齐全不构成统一启动障碍；缺口只限制依赖该信息的判断或动作。辅助研究维度用于支持主问题，不自动增加复现目标。

用户确认研究方案后开始真实研究。必要澄清和方案调整可以在执行中进行；已经确认的目标和条件不机械重做。

## 3. 研究骨架

CS 论文复现 Workflow 保留六项核心职责和一项条件职责。

| 研究节点 | 类型 | 交出的研究结果 |
|---|---|---|
| 复现基线与判据确定 | 核心 | 与目标对应的参考结果、实验条件及比较依据 |
| 复现实验方案设计 | 核心 | 能够检验目标的实验安排、执行要求和成本边界 |
| 执行准备与条件核验 | 核心 | 已准备的代码、资源、环境及执行条件结论 |
| 真实执行与结果取得 | 核心 | 可追溯的实际执行、原始输出和实验结果 |
| 结果可比性与达标判断 | 核心 | 逐项目标的可比性、结果差异和达标判断 |
| 复现结论与下一步建议 | 核心 | 范围明确的复现结论、证据记录和后续建议 |
| 偏差诊断与验证 | 条件 | 对关键差异的解释、验证结果和剩余未知 |

首次完整复现以表中六项核心职责为基准路径。偏差诊断在影响判断或下一步行动时进入，结果返回受影响的研究工作。

核心职责必须得到符合要求的正式结果，可以由本次研究形成，也可以由仍然适用的已有成果满足。未开展、执行失败或暂不可用不等于职责已满足；仍有缺口时按第 8 节表达和收口。职责划分不等于每个项目必须新建同样数量的任务或逐项重新执行。

## 4. 节点职责

### 4.1 复现基线与判据确定

**研究问题：** 本次具体检验哪项结果，在什么条件下、依据什么判断？

**输入：** 已确认的复现目标、论文及补充材料、对应实现、参考结果和已有比较协议。

**结果：** 建立“目标结果—实验条件—参考结果—来源—比较判据”的对应关系。数值结果明确指标含义、方向、尺度、数据范围和汇总方式；非数值结果采用与目标主张相符的检验要求。来源冲突保留差异与采用依据，官方身份不代替实验对应关系核验。

**职责边界：** 判据应来自参考来源、适用评测协议或经确认的本次比较要求，并尽量在正式运行前确定。来源未规定的容差不能随意补造，也不默认要求数值逐位相等。判据尚未确定时，可按授权取得结果并报告差异，达标判断保留未知。看到结果后新增或改变判据，须说明依据及其对结论的影响，并按方案变更规则处理，不能迁就结果降低标准。

### 4.2 复现实验方案设计

**研究问题：** 怎样获得足以检验本次目标的真实结果？

**输入：** 复现目标、已取得的基线与判据、现有条件、关键缺口和资源约束。

**结果：** 明确每项目标对应的实验、采用的实现、所需资源、关键配置、训练或评测协议、结果取得方式及预期成本。涉及随机性、多次运行或统计结论时，说明有依据的重复、选择和汇总规则。采用非官方或独立实现时，明确与论文方法的对应关系及必要验证。

**职责边界：** 来源明确要求、来源未指定而由系统选择的执行细节、有意偏离参考设定的安排分别记录。影响科研含义的差异需要专业判断；触及已确认边界时调整研究方案。小规模试运行用于核验所覆盖的条件，不能替代正式训练、实验覆盖或评测范围。本节点形成实验安排和要求，不把计划记为已执行，也不另建第二套研究方案。

### 4.3 执行准备与条件核验

**研究问题：** 当前真实条件是否足以按方案执行？

**输入：** 具体实验安排、代码与必要修改、资源要求、环境要求和执行边界。

**结果：** 准备可追溯的代码、数据、模型和配置，针对真实执行入口核验环境、输入交付和资源条件，明确哪些实验可执行、哪些缺少必要条件及其影响。每份资源分别保留身份、用途和状态；不适用的资源要求如实说明。

**职责边界：** 来源未规定的纯运行细节，由系统在不改变科研含义和已确认边界的前提下选择并记录。依赖安装完成不等于运行就绪；必要输入或关键执行条件无法确认时，暂缓受影响动作。准备结果只证明已准备什么及其可用性，程序实际使用情况由执行证据证明。

### 4.4 真实执行与结果取得

**研究问题：** 实际执行了什么，得到了什么结果？

**输入：** 实验方案、有效的条件核验结果，以及本次冻结的执行输入与边界。

**结果：** 完成授权范围内的真实实验，保留代码、资源、环境、实际配置、运行状态、原始输出与所得结果之间的对应关系。核验关键资源的实际使用与执行前固定输入是否一致；完成、部分完成、中断、失败和结果未知分别记录。

**职责边界：** 指标和其他结果来自所属实验的真实输出，提取、换算与汇总可追溯。参考值、历史成绩和计划字段不补入本次实测结果，不跨运行拼接或只挑成功项。多次运行遵守已确定的选择与汇总规则；恢复同一次运行不计为新的独立实验。程序退出成功不直接证明复现达标。

### 4.5 结果可比性与达标判断

**研究问题：** 本次结果能否与参考结果比较，各项目标是否达到判据？

**输入：** 目标对应的实际结果、参考结果、比较判据和双方实验条件，以及必要的执行核验与诊断结果。

**结果：** 针对每项目标说明比较是否成立、实际差异、采用的规则、达标判断及限制。核验影响结论的任务范围、数据划分、预处理、训练与评测方式、指标与汇总口径、实现差异，以及相关随机性或硬件条件。

**职责边界：** 先确认可比性，再作达标判断。同名指标或相近数值不构成可比依据；异常高分同样需要有效性核验。测试数据用于训练或选参等情形，应明确其对比较的影响。条件不足时保留观察到的差异与无法判定，不将差异直接解释为方法优劣，不为适配结果改写判据。

### 4.6 复现结论与下一步建议

**研究问题：** 本次复现到什么程度，下一步是否值得继续？

**输入：** 逐项目标的比较结果、证据覆盖、有效诊断、尚未解决的缺口，以及当前资源和研究边界。

**结果：** 直接回答用户的复现目标，说明已完成范围、结论依据、限制和必要下一步，形成可追溯的复现记录。结论可回到对应实验、实际结果、参考来源和比较依据。

**职责边界：** 部分结果达标只支持相应范围，不扩写为整篇论文复现成功。下一步建议围绕能够改变判断的补证、条件修正或必要验证，也可以明确当前范围无需继续。科研建议、系统执行决定和项目完成判断分别负责；记录组装与报告呈现保存已有研究结果，不在汇总时补出未经研究形成的结论。

### 4.7 偏差诊断与验证

**进入条件：** 未达标、异常高分、运行间差异、来源冲突或执行偏离可能实质改变结论或下一步行动。

**输入：** 待解释差异、对应计划与实际记录、比较结果和已有证据。

**结果：** 区分已有证据支持的原因、待验证解释和剩余未知；针对有价值的解释安排必要验证，说明不同结果会怎样改变判断。验证结果回到受影响的条件、比较或结论。

**职责边界：** 合理猜测保持假设身份，不写成已确认根因。一般网络、文件和进程故障由执行能力处理。缺乏进一步验证价值时，可在完成要求允许的范围内带限制交付；如实报告未达标不以查明全部原因作为前提。

## 5. 科研依赖与结果复用

依赖由所需事实及其用途决定，不以固定前一步代替。

| 判断关系 | 依赖要求 |
|---|---|
| 形成具体实验方案 | 对应明确的复现目标，并区分已有基线与待补缺口 |
| 开展真实实验 | 具有满足该实验的执行条件及有效授权 |
| 判断结果达标 | 具有所属实验的可信实际结果、对应参考、合法判据和有效可比性结论 |
| 形成复现结论 | 具有相应比较结果，或足以说明无法判定的缺口与限制依据 |

各节点可直接引用所需的正式事实和结果，无需相邻节点重复转述。基线核查、方案细化与准备工作可按实际信息依赖安排，不能把展示顺序变为没有科研依据的串行限制。

复用前检查来源、版本、实验条件、当前目标和新增证据，确认成果仍满足相应工作要求。历史结果保持历史身份；用户要求新的真实运行时，历史成绩不能替代本次实验。

代码、资源、关键配置、实验协议或比较判据发生实质变化时，只重新核验受影响的准备、结果和判断。已有真实执行保留为历史事实，失去当前适用性的结论不继续作为依据。

## 6. 持续推进与用户参与

每项结果经检查接受后更新科研状态（ScientificState），由新的执行决定（ExecutionDecision）确定下一步。重复执行使用原研究任务身份，通过新的执行工单（WorkUnit）冻结本次输入；技术恢复不新增独立实验事实。

执行顺序、次数和能力可以在已确认依赖与边界内调整。新增或删除研究任务、修改依赖、工作要求、完成要求或已确认边界时，按 OpenAIR 规则形成新方案并重新确认。

局部失败只影响相关动作，已有可信结果继续保留和交付。系统负责一般运行故障、技术配置和恢复；只有继续研究所必需的信息确实只能由用户提供，或需要确认研究边界变化时，才请求用户参与。

显著高成本执行前，明确本次运行将解决哪个关键判断、预期消耗和允许的执行范围。超出已确认预算或风险边界时取得用户确认；边界内按用户选择的推进方式执行。继续运行的预期价值不足时，按完成要求判断是否收口，不为流程完整持续追加实验。

## 7. 能力与接入边界

Workflow 定义保存本合同对应的研究结构、必要依赖及研究工作要求的稳定引用；Planner 结合项目目标形成研究方案，Compiler 检查后提交确认。研究方案保留所用 Workflow 引用，执行时选择满足工作要求的 Agent 或 Skill。

检索、阅读、资料整理、版本获取、资源下载、依赖安装、日志解析和记录打包等按当前职责需要使用。它们是完成研究工作的能力，不能代替实验设计、条件核验、真实执行、比较和结论的责任，也不因工具数量增加固定研究节点。

已经定义为独立项目研究任务的工作，分别经过正式执行决定、工单和结果检查。任务内部可以组织多个技术步骤，不顺带标记其他独立研究任务完成。条件职责按其进入条件安排，所需判断尚未满足时不能用“已跳过”替代。

Agent 或 LLM 负责科研含义、可比性和专业取舍；代码负责确定性的身份、来源、结构、约束校验、指标计算和数据连接。完整事实保存在各自正式对象中，模型读取当前判断所需信息。复现记录关联这些事实，不形成第二套资源、科研状态或项目完成依据。

## 8. 复现判定与最终交付

分别表达三类结果：**程序执行到哪里、证据是否足够、科研目标是否达标**。

| 科研判定 | 成立条件 |
|---|---|
| 复现达标 | 对应执行与结果可信，必要证据充分，比较条件成立，并满足有依据的判据 |
| 复现未达标 | 具备有效执行、必要证据和可比条件，但实际结果未满足判据 |
| 无法判定 | 缺少必要执行、有效结果、参考依据、可比条件或合法判据，尚不足以作出前两种判断 |

多个目标分别判断，总体结论遵循研究方案的完成要求，不只选择成功项报告。环境失败、计算中断或缺少可比较结果，不等于证明论文结果无法复现；本次未达标也不直接证明论文错误。

有效成果在研究过程中持续可见。最终交付明确：**复现范围与结论、实际结果及参考比较、可信执行依据、限制与缺口、下一步建议**。用户能够从关键结论核查对应的代码、必要资源、环境、实际运行、原始结果和比较来源。

研究达到已确认完成要求，或满足方案中允许保留明确缺口的收口条件时，由完成判断（CompletionDecision）决定是否结束，并按正式机制生成、校验和保存最终结果。当前方案不允许带缺口结束时，保留未完成状态或按正式流程调整方案。

项目结束与复现达标分别表达。方案生成、程序退出、节点完成、记录组装或预算耗尽，都不能单独证明用户的复现目标已经达成。
