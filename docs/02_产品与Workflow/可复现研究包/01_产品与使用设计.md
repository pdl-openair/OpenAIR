# 01｜Research Package 产品与使用设计

> 状态：v0.3 定稿  
> 日期：2026-09-28

## 1. Research Package 解决什么问题

一项研究完成后，真正有价值的内容往往散落在论文、代码、数据、运行记录、配置和研究者经验里。下一位科研人员即使拿到了这些材料，仍可能需要重新判断：方法解决什么问题、哪些结果在什么条件下成立、关键资源版本是什么、哪些边界不能丢，以及哪些范围其实没有验证。

Research Package 把这些成熟内容整理成一个**可版本化、可追溯、可继续使用的研究起点**。

它减少的是新研究开始前重复发生的理解、查找、配置和试错，而不是替代新的研究判断。

## 2. 两类用户

### 贡献者

贡献者希望把已经形成的真实研究中值得复用的部分交给后来者。

贡献者可以是原研究完成者，也可以是能够理解、核查并确认真实来源和科研语义的成果整理者。整理者不取得原作者身份；必须区分作者报告、第三方核验与当前项目实际验证，不因整理或发布而提高原验证强度。

系统应优先复用已有研究成果和来源，贡献者主要补充机器无法可靠确定的科研语义，例如：

- 这套方法解决什么问题；
- 参考实例实际验证了什么，验证到什么程度；
- 哪些条件会影响结果含义或可信度；
- 哪些内容迁移时应保持，哪些可以调整；
- 哪些限制、冲突和未验证范围仍然存在。

形成 Package 不应要求贡献者重新录入整个旧项目，也不要求为了发布 Package 重新搭建专用 Workflow、Skill 或执行环境。

对于 OpenAIR 内已接受、可追溯且内容与科研语义未变化的成果，系统应复用已有成果和对应确认记录，自动准备研究包内容，不要求贡献者逐包重新审核全部产出。已有确认只覆盖其实际确认的内容、版本和边界，不能扩展到新生成的科研结论。

系统先核查新增或变化的复用语义；只有会影响可信度或复用判断、且系统无法可靠确定的重要事项，才请求贡献者补充或确认。贡献者明确确认包的纳入范围、必要新增内容和限制，这一动作应尽量与最终成果确认合并，并绑定实际包版本与内容。自动形成不表示自动公开分享。

外部成果整理也遵循同样的最小新增人工原则。有可追溯既有核查记录时应考虑复用；没有记录时如实区分来源报告与当前核查，不默认要求用户整份逐项重审外部材料。

### 使用者

使用者面对新的科研问题，希望在已有成果上继续推进，而不是从零恢复原研究。

拿到 Package 后，应能独立看懂：

- 这套方法曾经解决什么问题；
- 哪些参考实例在什么研究对象和条件下得到了什么结果；
- 原研究实际完成了什么验证，依据和边界是什么；
- 哪些代码、数据、模型、配置或其他资源可以继续利用；
- 哪些条件需要保持，哪些内容可以调整；
- 哪些限制、未知或条件差异会影响当前复用。

Package 提供的是**可利用的已有研究起点**。当前项目最终采用什么、需要补什么证据、怎样继续，由当前问题和正式研究机制共同决定。

## 3. 用户怎样使用

```text
已有研究成果
→ 形成 Research Package
→ 分享 / 导入
→ 看懂方法、实例、资源和边界
→ 与当前问题、条件和已有事实一起进入研究规划
→ 继续新的研究
```

新的项目可以直接参考仍然适用的方法和结果，也可以重新核验关键事实、在条件变化后调整方法、只复用其中一部分，或在可信度确实依赖重新执行时进行复现。

一个项目可以引用一份或多份 Package。不同 Package 的来源、版本、适用条件和冲突分别保留，不因为进入同一项目而失去各自来源。

## 4. 用户首先应该看到什么

用户查看一份 Package 时，首先应看到：

1. **它解决什么问题；**
2. **原研究验证过什么；**
3. **这些结果对应什么研究对象和条件；**
4. **关键结果是什么、在哪里可以核查；**
5. **哪些资源可以继续利用；**
6. **哪些内容需要保持、可以调整或仍需重新核验。**

来源、版本、结构字段和内部追溯关系可以进入详情层。产品不要求用户先阅读 YAML 或理解 OpenAIR 内部对象，才能获得上述信息。

## 5. 一个有价值的 Package 应包含什么

| 内容 | 用户获得的价值 |
|---|---|
| **可复用方法** | 方法解决什么问题，需要什么输入，核心研究逻辑是什么 |
| **已验证参考实例** | 原研究在什么对象和条件下验证了什么，得到什么结果，验证依据和边界是什么 |
| **资源来源** | 代码、数据、模型、配置、SOP、文档等从哪里取得，关键版本是什么 |
| **适用与调整边界** | 什么需要保持，什么可以调整，哪些范围仍未验证 |
| **能力需求** | 继续这类研究通常需要哪些研究能力 |

参考实例中的结果保留真实科研性质和上下文。实验观测、计算结果、模型预测、来源报告或其他结果不能在进入 Package 后失去区别；会影响理解的研究对象、条件、方法、不确定性和具体来源位置也应保留。

## 6. “可复现”意味着什么

Research Package 应让后来者能够追溯原方法、参考实例和关键资源，并在需要时判断怎样重新核验或复现。

是否重新执行取决于当前问题、条件差异、证据需求和可信度要求。两个事实始终分开：

```text
Package 中存在已验证参考实例
≠
当前项目已经重新验证

Package 中记录了资源
≠
当前项目已经取得或实际使用该资源
```

## 7. 产品成功的判断

Research Package 真正产生价值时，应同时看到三个结果：

1. **贡献成本低**：成熟成果能从已有研究中整理出来，而不是重新录入整个项目；
2. **接手成本低**：未参与原研究的人不依赖原作者持续解释，也能理解可复用的研究起点；
3. **继续研究更快**：用户把时间用于新的科研问题，而不是重新恢复已经解决过的前置工作。

具体证据和通过条件见 [04｜Research Package 验收合同](04_验收合同.md)。
