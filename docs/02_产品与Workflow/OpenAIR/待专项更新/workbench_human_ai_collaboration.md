# 主工作界面与人机协作设计

## 1. 文档作用

本文用于说明 OpenAIR 主工作台的基本页面结构和人机协作方式。

当前设计稿主要表达两类场景：

- 计算机科研增强场景；
- OpenTrajectory / 材料科研分析场景；
- 压电材料任务场景。

这些设计稿只作为工作台结构参考，不代表产品要写死某个领域流程。

## 2. 主工作台定位

主工作台是用户推进科研任务的核心入口。

它负责：

- 接收自然语言科研目标；
- 展示当前任务阶段和系统输出；
- 承接用户确认、修改、补充和跳过；
- 展示阶段结果和当前产物；
- 触发下一步任务执行；
- 保留任务过程中的关键记录。

它不负责：

- 展示完整系统内部节点树；
- 暴露全部底层 Skill 调用细节；
- 作为复杂日志面板；
- 写死材料或计算机某一类任务页面。

## 3. 页面基本结构

主工作台建议采用三栏结构：

```text
左侧任务流 / 阶段导航
中间主内容流 / 阶段结果展示
右侧人机协作区 / 确认与追问
```

| 区域 | 作用 |
|---|---|
| 左侧任务流 | 展示四阶段进度、当前阶段、阶段风险和待处理提示。 |
| 中间主内容流 | 展示系统对当前阶段的分析结果、表格、图谱、方案、证据包、报告片段等。 |
| 右侧协作区 | 展示 AI 助手消息、系统提醒、用户确认、补充问题、快捷操作和下一步建议。 |

## 4. 主内容流

主内容流应采用“阶段结果 + 可插拔结果块”的结构。

典型结果块包括：

- 任务理解；
- 研究语境；
- 文献/资料候选列表；
- 筛选理由；
- 方案设计；
- 参数表；
- 证据网络；
- 关键链路；
- 研究线索；
- 报告片段；
- 产物入口。

结果块应面向科研用户表达，不展示过多内部字段、抽取类别、Schema 细节和技术实现过程。

## 5. 人机协作区

右侧协作区是用户与系统协同推进任务的位置。

它应支持：

- 系统解释当前结果；
- 向用户提出必要确认；
- 提供快捷操作；
- 接收用户补充；
- 提醒风险和缺失信息；
- 触发继续分析、重试、跳过、返回修改。

确认方式应尽量轻量：

```text
优先选择 / Y-N / 默认建议 / 快捷按钮
必要时再让用户输入长文本
```

### 5.1 用户可见叙事契约

右侧协作区不应直接把内部 trace、工具原文、配置路径或长 Markdown 当作普通用户正文展示。后端 / Agent / 前端统一使用 `userFacingNarrative` 表达用户可见叙事：

- `summary`：普通科研用户默认看到的短摘要，说明刚发生了什么、有什么影响、下一步建议是什么。
- `detailMarkdown` / `detailText`：原始 Markdown、工具输出、技术说明或长内容，默认折叠，仅在用户展开详情时显示。
- `sourceType` / `sourceId`：用于关联原始消息、能力调用、产物或确认项，方便开发视图追溯。
- `severity` / `suggestedActions`：用于表达阻塞、风险和可选操作。

该契约只负责“如何说给用户听”，不替代核查 Agent 对产物可信度的判断，也不替代总结 Agent 对阶段产物的正式沉淀。旧数据没有 `userFacingNarrative` 时，前端可以做兼容摘要，但后续真实 Agent 输出应优先直接提供该字段。

## 6. 工作台中的状态表达

任务级状态（看板）共 4 种：

```text
进行中 / 等待确认 / 已完成 / 已失败
```

阶段级状态（工作台内各阶段节点）共 4 种：

```text
未开始 / 进行中 / 已完成 / 已失败
```

任务一旦创建并开始问答即为"进行中"，不存在任务级"未开始"；阶段节点不涉及确认流程，确认是任务级行为。

状态不是为了展示系统内部流程，而是为了让用户知道：

- 当前做到哪一步；
- 是否需要自己处理；
- 系统刚刚产出了什么；
- 下一步会发生什么。

## 7. 设计稿中的可保留要点

当前设计稿中可保留的关键方向：

- 左侧阶段流清楚表达任务推进位置；
- 中间区域以阶段结果和产物为主，不做聊天堆叠；
- 右侧保持人机协作区，适合确认、追问和操作；
- 结果块支持表格、证据网络、方案、参数表等多种科研内容；
- 深浅色风格可以作为视觉参考，但信息结构优先于装饰。

## 8. 设计稿中需要避免的问题

后续开发时要避免：

- 把 OpenTrajectory 老页面直接照搬；
- 把材料字段写死到通用工作台；
- 过度展示底层抽取类别和技术对象；
- 在默认视图中展示复杂图谱和长日志；
- 用过多 icon、装饰和假精致效果干扰科研信息；
- 把确认流程设计成大量长文本输入。

## 9. 前端开发提示

主工作台第一版优先实现：

- 页面三栏布局；
- 四阶段导航；
- 主内容流容器；
- 可插拔结果块；
- 人机协作区；
- 基于 fixtures 的流程样例展示；
- 与后端任务状态接口预留字段对齐。

第一版不要求实现完整科研能力，但要保证页面结构能承接后续不同领域流程。
