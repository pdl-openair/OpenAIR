# 任务看板与产物管理设计

## 1. 文档作用

本文用于说明 OpenAIR 任务看板、任务详情和产物管理的基本设计边界。

当前设计稿主要表达两个层级：

- 看板总览；
- 任务详情。

后续产品还会增加态势看板，用于展示平台效能、任务运行统计、协同情况和 Skill 使用情况。

## 2. 看板总览定位

任务看板用于让用户快速判断：

- 当前有哪些任务；
- 每个任务处于哪个阶段；
- 已经产出了什么；
- 哪些任务需要处理；
- 哪些任务有风险；
- 哪些任务值得继续跟进。

任务看板不应变成节点树、长日志列表或复杂图谱入口。

## 3. 看板总览结构

看板总览建议包含：

- 筛选区：领域、团队/空间、时间范围、关键词；
- 顶部统计：运行任务、待决事项、关键产物、高风险任务；
- 本周/近期判断：突出当前最重要的任务状态；
- 任务卡片：展示任务名、阶段、关键进展、价值产物、风险和下一步；
- 侧边信息：待决事项、高风险提醒、重要产物。

任务卡片建议展示：

| 字段 | 说明 |
|---|---|
| 任务名称 | 用户能理解的科研任务名称。 |
| 所属流程 | 如材料科学、计算机科学、OpenTrajectory 分析等。 |
| 当前阶段 | 四阶段之一。 |
| 关键进展 | 当前真正推进了什么。 |
| 判断 / 状态 | 当前系统或用户需要关注的判断。 |
| 价值产物 | 当前可查看、可判断、可复用的产物入口。 |
| 风险与下一步 | 当前风险、待确认项和推荐操作。 |

## 4. 任务详情定位

任务详情用于查看单个任务的完整过程。

它负责展示：

- 当前阶段；
- 当前状态；
- 关键进展；
- 阶段产物；
- 能力调用记录；
- 风险提醒；
- 失败原因；
- 下一步建议；
- 进入主工作台继续处理的入口。

任务详情不是默认工作区。用户需要处理内容时，应进入主工作台继续协作。

## 5. 任务详情结构

任务详情建议包含：

- 顶部任务概览：任务名、所属流程、当前阶段、当前状态、最近更新时间、负责人；
- 左侧阶段导航：四阶段状态；
- 中间详情区：关键进展、阶段产物、能力调用、阶段判断、运行记录；
- 右侧操作区：待确认事项、风险提醒、下一步建议、进入主工作台按钮。

任务详情要能支撑回看，而不只是当前运行状态。

## 6. 产物管理

OpenAIR 的产物不是普通附件，而是科研任务推进中形成的可复用结果。

典型产物包括：

- 任务理解；
- 初始假说；
- 研究方案；
- 文献/资料候选集；
- 证据包；
- 机制链路；
- 计算结果；
- 实验记录；
- 参数表；
- 研究线索；
- 报告片段；
- 复用输入包。

产物至少需要记录：

| 字段 | 说明 |
|---|---|
| artifact_id | 产物唯一标识。 |
| task_id | 所属任务。 |
| stage | 所属阶段。 |
| artifact_type | 产物类型。 |
| title | 面向用户展示的标题。 |
| summary | 简短摘要。 |
| source | 来源：系统生成、用户上传、Skill 返回、外部导入等。 |
| related_capability_calls | 关联能力调用。 |
| version | 版本。 |
| created_at | 创建时间。 |

## 7. 能力调用记录

能力调用记录用于说明系统用了哪些 Skill / 工具 / 模型推进任务。

它不需要在看板总览中完整展开，但必须在任务详情中可查看。

能力调用记录建议包含：

- 调用能力名称；
- 所属 Skill；
- 调用阶段；
- 输入摘要；
- 输出摘要；
- 状态；
- 耗时；
- 失败原因；
- 关联产物。

## 8. 态势看板补充说明

态势看板是独立页面，不等同于任务看板。

它主要用于展示平台整体效能和协作情况，例如：

- 运行中任务数量；
- 不同阶段任务分布；
- 任务平均推进时长；
- 失败 / 重试情况；
- Skill 调用频次；
- 高价值产物数量；
- 人工确认次数；
- 团队协作情况。

态势看板优先服务团队管理和平台迭代，不直接承接单个任务内容处理。

## 9. 第一版开发重点

第一版优先完成：

- 任务看板基础列表；
- 任务卡片；
- 任务详情基础布局；
- 产物入口；
- 能力调用记录入口；
- 基于 fixtures 的流程样例展示。

暂不做复杂权限、跨团队统计、复杂报表和完整态势分析。
