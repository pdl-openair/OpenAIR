# OpenAIR 产品定义与边界

## 1. 文档作用

本文用于统一 OpenAIR 的产品口径，明确平台面向谁、解决什么科研问题、能力做到哪里，以及哪些内容不在平台本体范围内。

本文作为后续界面设计、任务看板、案例流程适配和技术开发的共同依据。科研任务模型、节点状态与看板表达规则在《OpenAIR 通用科研任务模型与看板规则》中定义，本文不重复展开。

## 2. 平台定位

OpenAIR 是面向科研任务推进过程的智能工作平台。核心是把自然语言科研目标组织成可执行、可追踪、可回溯、可复用的科研任务过程。

平台以自然语言交互为入口，将研究目标组织为“问题建模 → 方案设计 → 执行验证 → 洞察生成”的任务主线，并通过任务看板呈现关键进展、价值产物、能力调用、风险和下一步操作。

OpenAIR 不替代科研判断。系统负责检索、整理、抽取、分析、生成和记录；用户负责目标确认、关键选择、结果判断和后续决策。

OpenAIR 可面向不同科研领域组织任务过程。材料科学研究、计算机科学研究、材料科研分析与线索生成等任务，都可以基于 OpenAIR 的统一任务主线进行适配。

## 3. 目标用户

| 用户类型 | 典型需求 |
|---|---|
| 科研人员 / 研究生 / 工程师 | 输入研究目标，组织资料、数据、工具和阶段产物，获得可追溯的分析结果与后续建议。 |
| 课题负责人 / 项目负责人 | 查看任务进展、关键产物、风险点和可复用结果，判断下一步研究方向。 |
| 平台建设与技术团队 | 接入模型、工具、数据源和案例流程，将科研过程沉淀为可复用任务能力。 |

第一版优先服务有明确科研问题、需要多步骤推进、过程产物需要留痕复用的科研任务。

## 4. 适用范围与优先流程

OpenAIR 第一版优先服务有明确研究目标、需要多阶段推进、过程产物需要持续沉淀的科研任务。

当前优先验证三类代表性流程：

| 优先流程 | 说明 |
|---|---|
| 计算机科学研究流程 | 面向文献调研、研究问题凝练、实验设计、任务拆解、代码实验和论文写作，例如论文复现、代码检索增强、模型评测等任务。 |
| 材料科学研究流程 | 面向文献/数据库检索、工艺参数推荐、计算/实验执行、表征分析和报告生成，例如 AlN、MoS₂、Flux 等材料任务。 |
| 材料科研分析与线索生成流程 | 面向资料筛选、证据整理、机制链路分析和研究线索生成，可作为材料科研中的分析型流程实践。 |

三类流程形态不同，但验证的是同一套平台能力：OpenAIR 能否把不同科研任务稳定组织到“问题建模 → 方案设计 → 执行验证 → 洞察生成”的主线中，并保留状态、产物和回溯关系。

## 5. 能力边界

OpenAIR 平台本体不按具体领域能力定义，而按它在科研任务中的职责定义。

| 层级 | 负责什么 |
|---|---|
| OpenAIR 平台本体 | 接收科研目标，组织四阶段任务过程，呈现看板状态、关键进展、价值产物、能力调用、风险和下一步操作。 |
| 场景流程 | 将通用任务规则适配到具体科研领域，定义阶段节点、执行方式、产物结构和能力调用方式。 |
| 底层能力支撑 | 提供模型、工具、数据源、设备、算力、流程编排和能力治理，支撑场景流程执行。 |

OpenAIR 不做成单轮问答产品、通用项目管理工具、模型训练平台、设备控制平台或能力治理平台。

## 6. 与场景流程和协同开发平台的关系

OpenAIR 与协同开发平台都是平台，但面向的用户和解决的问题不同。

| 对象 | 关系说明 |
|---|---|
| OpenAIR | 面向科研用户，提供统一的任务入口、四阶段任务主线、任务看板、人机协作和产物管理。 |
| 领域流程 | 作为 OpenAIR 内的任务适配方式，将通用任务规则落到材料科学、计算机科学、材料科研分析等具体任务中。 |
| 协同开发平台 | 面向能力建设与维护人员，提供模型、工具、数据源、设备、算力、Skill / Pipeline、流程运行和能力治理支撑。 |

新增领域时，不重新定义 OpenAIR 平台本体；只增加对应的流程模板、节点配置、产物样例、人机确认点和能力调用方式。

真实任务运行产生的日志、结果、失败点和能力短板，可以反向反馈到能力建设侧，用于后续能力迭代。
