# TASKLIST 与长程任务治理

主要用于线上 GPT / Agent 推进复杂、长期、多轮任务。

适用于：

- 一个产品目标需要分多轮完成；
- 一次盘点发现多个问题；
- 多个 Task 存在先后依赖；
- 执行过程中持续出现新事实；
- 任务需要跨对话、跨施工者继续推进。

## 核心原则

> **围绕最终产品目标，拆出可执行、可验收、对真实产品效果有贡献的 Task，并持续控制顺序、边界和完成状态，直到施工路线和产品目标完成。**

TASKLIST 是执行控制工具。

它负责让长程任务持续沿着正确路线推进。

---

## 1. 先锁定最终目标

写 Task 前先明确：

- 最终要解决什么产品问题；
- 用户最终得到什么改善；
- 什么结果能够证明目标完成。

最终目标用产品结果描述。

例如：

> 真实研究链可以稳定完成，局部模型失败不会摧毁已有结果，用户最终能够得到可信的下一步科研建议。

后续每个 Task 都必须能够说明：

> **它怎样推进这个最终目标。**

---

## 2. 拆成真正可完成的 Task

一个 Task 解决一个清楚的问题闭环。

每个 Task 至少写清：

```text
目标=
对最终目标的贡献=
当前事实基线=
依赖=
允许范围=
明确边界=
Done=
停止条件=
```

好的 Task 应该：

- 可以独立推进；
- 可以明确验收；
- 完成后产生真实进展；
- 范围足够集中；
- 同时完整解决当前根因。

Task 大小由真实问题决定。

文件数量、问题数量和修改行数只作为参考。

---

## 3. 按依赖和产品价值排路线

任务顺序重点看：

1. 哪些是后续工作的前提；
2. 哪些处在当前关键路径；
3. 哪些直接影响产品正确性和用户结果；
4. 哪些完成后能够消除一整类后续问题。

存在依赖的 Task 按顺序推进。

互相独立、写入范围清楚的任务可以并行。

单条施工线默认一次只保持一个当前 Task。

每个 Task 完成后，下一 Task 基于最新事实和最新代码重新开始。

---

## 4. 执行过程中持续维护 TASKLIST

TASKLIST 随真实进展更新。

至少保持这些状态清楚：

- `WAITING`
- `CURRENT`
- `BLOCKED`
- `DONE`

发现新问题时先判断：

1. 是否直接影响当前 Task；
2. 是否属于当前根因；
3. 是否改变原有依赖或优先级；
4. 是否影响最终产品目标。

属于当前闭环的，纳入当前 Task。

属于后续工作的，进入后续 Task。

出现改变产品方向、正式设计或整体路线的重要新事实时，回到总控重新确认。

---

## 5. 分三层判断完成

### Task 完成

当前 Task 的目标和 Done 全部满足。

### 路线完成

计划中的关键 Task 已完成，依赖关系已经收口，没有遗漏当前路线中的关键问题。

### 产品目标完成

用真实产品结果验证：

- 最终用户问题得到解决；
- 真实链路符合预期；
- 关键质量和稳定性达到目标；
- 没有被 Task 状态掩盖的产品缺口。

TASKLIST 的设计目标是：

> **让路线完成尽可能直接意味着产品目标完成。**

最后仍以真实产品结果完成闭环。

---

## 6. 保证长程任务可以恢复

TASKLIST 应让新的 GPT / Agent 快速知道：

- 最终目标是什么；
- 哪些决定已经确定；
- 哪些 Task 已完成；
- 当前 Task 是什么；
- 当前事实基线是什么；
- 当前阻塞是什么；
- 下一步是什么。

保留执行需要的信息。

详细设计进入正式设计文档，历史案例和证据进入对应记录。

---

# 快速检查一个 TASKLIST

### 1. 最终目标清楚吗？

能否直接说清最终产品结果和用户改善？

### 2. 每个 Task 都有价值吗？

每个 Task 能否说明自己怎样推进最终目标？

### 3. Task 能独立验收吗？

目标、边界和 Done 是否明确？

### 4. 路线顺序正确吗？

依赖、关键路径和优先级是否清楚？

### 5. 新问题有地方去吗？

执行过程中发现的问题能否明确进入当前 Task、后续 Task 或重新规划？

### 6. 全部完成后，产品目标大概率会完成吗？

如果所有 Task 都通过，但仍明显可能无法实现最终产品目标，说明 TASKLIST 还缺关键工作或验收。

---

## TASKLIST 完成检查

- [ ] 最终产品目标明确。
- [ ] 用户可见结果明确。
- [ ] 每个 Task 都对最终目标有直接贡献。
- [ ] 每个 Task 都可以独立验收。
- [ ] 任务依赖和顺序清楚。
- [ ] 当前 Task 唯一明确。
- [ ] 新问题有明确归属规则。
- [ ] 每轮都基于最新事实继续。
- [ ] 路线完成有整体检查。
- [ ] 最终有真实产品目标验收。
