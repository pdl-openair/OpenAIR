# 施工验收检查

用于代码应用、测试、真实 E2E 和任务完成前检查。

**按当前任务需要完成对应层级验证。**

影响真实运行链、模型能力或用户结果的改动，需要进入真实生产路径验证。  
纯文档、明确的静态配置或局部工程改动，完成与其风险相匹配的验证即可。

## 1. 代码应用后

- [ ] 当前仓库、分支和 HEAD 正确。
- [ ] 实际修改范围符合当前任务。
- [ ] 已有无关修改没有被覆盖。
- [ ] 没有意外删除、乱码或无关格式化。
- [ ] `git diff --check` 通过。
- [ ] `git status --short` 已检查。
- [ ] 实际 diff 已检查。

## 2. 测试通过后

- [ ] 针对当前根因的测试通过。
- [ ] 直接相关回归通过。
- [ ] 验证范围覆盖当前根因和直接影响。
- [ ] 测试验证的是当前正式产品规则。
- [ ] 调用成功和业务成功已经分别检查。
- [ ] 当前阶段真正完成了自己的职责。
- [ ] 下游能够正确使用本轮结果。
- [ ] 局部失败不会破坏已有有效结果。

## 3. 真实 E2E 前

需要进入真实运行验证的任务，检查：

- [ ] 当前运行环境已经加载最新代码。
- [ ] Provider、配置、依赖和服务状态正确。
- [ ] 当前数据来源和运行数据位置明确。
- [ ] 使用正式生产路径。
- [ ] 创建新的真实任务。
- [ ] 需要模型能力时使用真实 Provider。
- [ ] 需要检索或文献时使用真实来源。

## 4. 真实 E2E 后

- [ ] 用户最初的问题得到实际改善。
- [ ] 已完成结果保持稳定。
- [ ] 最终结果清楚、可信、可以使用。
- [ ] 依据、风险和不确定性清楚。
- [ ] 系统内部故障没有被错误变成用户问题。
- [ ] 新出现的第一真实失败点已经明确。

## 5. 宣布任务完成前

- [ ] 当前 Task 的 Done 条件全部满足。
- [ ] 正式设计、实现和真实行为一致。
- [ ] 当前完成状态准确。
- [ ] 关键验证证据可以追溯。
- [ ] 当前关键阻塞已经处理。
- [ ] 下一步明确。

符合当前任务验收层级后，再进入下一任务、提交或继续真实 E2E。
