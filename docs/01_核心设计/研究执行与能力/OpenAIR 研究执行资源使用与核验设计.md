# OpenAIR 研究执行资源使用与核验设计

> 状态：已确认  
> 更新时间：2026-09-20  
> 职责：规定需要由真实程序读取的正式资源怎样进入一次具体执行，以及系统怎样根据计划资源与实际资源的身份事实确定性核验实际使用关系。本设计只负责资源身份与使用关系核验，不负责 Provider 调用生命周期、远端执行状态、超时、取消或故障恢复。

---

## 1. 核心合同

当一次执行的可信性或复现含义取决于程序实际使用哪一份模型、数据、配置、checkpoint、tokenizer 或输入文件时，必须区分两个事实：

```text
计划使用的资源
≠
程序实际使用的资源
```

WorkUnit 中已经冻结某份正式资源，只能证明**本次计划使用哪一份资源**；不能单独证明程序运行时实际使用了同一份资源。

例如：WorkUnit 冻结模型 revision A，但程序运行时又根据模型名称联网解析到 revision B。此时计划资源是 A，实际使用资源是 B，两者不能视为同一事实。

因此，**资源使用核验**要求系统同时保留计划资源身份和实际资源身份，并按确定性规则确认二者是否一致。

---

## 2. 资源进入执行的主链

一份需要由真实程序读取的正式资源，应沿下面的关系进入执行：

```text
WorkUnit 冻结计划资源身份、用途和来源引用
→ 执行能力把该资源以可追溯方式交给程序
→ 程序运行
→ 执行记录保存程序实际使用的资源身份事实
→ 按确定性依据比较计划资源与实际资源
→ 形成核验结论
```

这条链中有三个必须保持的关系：

1. **计划事实可追溯**：能够确定本次计划使用哪一份正式资源，以及它来自哪个正式来源或稳定引用。
2. **资源交付可追溯**：程序取得资源的方式必须保持从 WorkUnit 中计划资源到真实程序输入的可核对关系。具体可以使用固定本地快照、不可变 revision、受控配置或其他可靠方式。
3. **实际事实可核验**：程序运行后必须能够取得足以识别实际资源的事实；如果实际身份无法确认，就不能把计划使用写成已经实际使用。

如果当前工作要求使用固定资源，但系统无法可靠建立计划资源与程序输入之间的关系，则该资源条件尚未得到满足。增加记录字段本身不能代替真实的资源交付关系。

---

## 3. 核验需要保存的事实

资源使用核验至少需要以下三类事实：

| 事实 | 必须能够回答的问题 |
| --- | --- |
| **计划资源事实** | 本次计划使用哪一份资源、用于什么、对应什么正式来源或稳定引用 |
| **实际资源事实** | 程序实际解析或读取到哪一份资源，能够用什么稳定身份识别 |
| **核验依据** | 计划身份与实际身份怎样确定性对应，以及依据什么判断一致或不一致 |

实际资源身份可以来自不同技术路径，只要能够稳定、确定地指向程序真实使用的资源。例如：

- 不可变 revision；
- 内容哈希；
- 已固定的本地快照；
- 能唯一对应正式资源的路径与身份记录；
- 其他能够按明确规则验证的稳定身份。

如果程序已经运行，但没有留下足够事实确认实际资源身份，则执行事实仍然存在，资源使用关系仍属于**未核验**。

---

## 4. 核验规则与结论

只有系统能够确定性回答以下问题时，才能确认“程序实际使用了计划中的同一份资源”：

1. WorkUnit 计划使用哪一份资源；
2. 程序实际使用哪一份资源；
3. 两个身份怎样对应；
4. 对应后的身份是否一致。

以下信息单独存在时，不足以完成核验：

- 只有资源名称；
- 只有会变化的分支、标签或“最新版”；
- 只有 WorkUnit 中的资源标识，没有程序实际使用侧的身份事实；
- 程序自行联网解析资源，而系统无法确认最终解析到哪一份。

只要计划身份与实际身份之间仍需要猜测、科研判断或语义推断，就不能声明资源使用已经核验。

核验结论具有三种语义：

| 情形 | 结论 |
| --- | --- |
| 计划身份与实际身份能够确定性确认一致 | **已核验**：可以声明本次程序实际使用了计划中的正式资源 |
| 程序已经运行，但实际身份或对应依据不足 | **未核验**：保留已经发生的执行事实，不声明实际资源已经确认 |
| 计划身份与实际身份能够确定性确认不同 | **不一致**：记录实际资源与计划资源不同，不把二者视为等价 |

资源使用核验只确认资源关系。核验失败、证据不足或身份不一致，都不能改写已经真实发生的程序执行事实。

---

## 5. 多资源执行

一次执行可以同时使用模型、数据、配置、checkpoint、tokenizer、参数文件等多份资源。

每一份需要核验的资源都必须独立保留：

- 计划资源身份和用途；
- 实际资源身份事实；
- 核验依据；
- 核验结论。

多份资源可以共享传递机制、缓存或目录，但共享执行方式不能合并各自的身份关系。某一份资源未核验或不一致，也不能覆盖其他资源已经取得的核验事实。

---

## 6. 与模型调用运行事实的职责边界

资源使用核验和模型调用运行事实可以关联，但不能互相替代。

必须保持：

```text
模型 / revision / checkpoint 等资源身份
≠
Provider request / execution / correlation identity

资源是否与计划一致
≠
模型调用当前是 running / completed / failed / cancelled / unknown
```

本设计负责回答：

> 程序实际使用的是哪一份资源，它是否与 WorkUnit 计划资源一致？

模型调用运行与故障恢复设计负责回答：

> 这一次 Provider 执行是否已经提交、当前处于什么运行状态、是否已经完成或失败、如何查询、取消和恢复？

因此：

- Provider request id、job id、execution id、correlation id 只能证明或关联一次执行，不能单独证明实际使用了哪一个模型 revision、checkpoint 或其他资源；
- 模型名称、revision、checkpoint 等资源事实可以进入资源使用核验，但不能单独证明一次 Provider 执行仍在运行或已经完成；
- 如果一次模型执行处于 `unknown`，已经取得的资源身份事实继续保留，但不能用资源核验结果替代执行状态核对；
- 如果资源核验发现不一致，应记录真实不一致；是否允许继续使用该执行结果，由对应能力合同和研究执行机制依据正式要求决定，本设计不越权作出运行或科研裁决；
- 调用故障、网络中断、远端状态查询和恢复属于模型调用运行合同，不进入资源核验合同的状态机。

这两个合同可以共享同一份执行记录中的不同事实，但必须保持各自唯一 Authority。
