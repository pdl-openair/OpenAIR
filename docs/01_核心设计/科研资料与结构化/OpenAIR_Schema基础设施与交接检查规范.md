# OpenAIR Schema 基础设施与交接检查规范

> 状态：已确认  
> 更新时间：2026-09-20  
> 职责：规定 Schema 的公共工程处理、模型服务技术适配，以及上下游正式数据交接的结构兼容性规则。

---

## 1. 核心处理模型

Formal Schema 和 Provider Schema 的正式语义一旦确定，后续解析、组合、转换、传输和校验只能改变技术表达，不能改变已经确定的结构语义和约束。

Schema 基础设施维护三条公共处理链：

```text
Provider Schema
→ 公共解析与引用处理
→ 转换为当前模型服务支持的技术表达
→ 调用前检查实际发送的 Schema
→ 模型调用

模型输出 + 确定性组装结果
→ 按 Formal Schema 校验
→ 结构合法的正式结果 / 结构失败事实

上游实际交接面
+ 下游输入结构要求
→ 交接兼容性检查
→ 允许交接 / 交接失败
```

这些公共处理必须由生产路径统一使用。业务节点不得分别维护等价的 Schema 解析、模型服务适配、正式校验或交接兼容逻辑。

---

## 2. 公共解析与正式校验

Schema 的解析、组合和引用处理由公共基础设施统一完成，包括 `$ref`、`$defs` 及其直接或递归依赖。

处理过程中必须保持所有会影响验证结果的正式约束。引用无法解析、依赖结构缺失或 Schema 本身无法形成可验证结构时，依赖该结构的处理失败。

模型输出完成确定性字段恢复和正式结果组装后，必须重新按 **Formal Schema** 校验。

```text
模型服务接受了技术 Schema
或
模型输出满足 Provider Schema
≠
最终正式结果已经满足 Formal Schema
```

模型服务侧的结构约束不能替代最终 Formal Schema 校验。

---

## 3. Provider Schema 的模型服务适配

Provider Schema 规定本次模型需要生成的结构；发送给具体模型服务前，可以转换为该服务支持的技术 Schema 表达。

转换必须满足：

```text
Provider Schema 的正式语义和约束
=
模型服务实际收到的技术 Schema 所表达的语义和约束
```

不同模型服务可以使用不同的 Schema 写法，但不能为了适配而删除、放宽或改写会影响验证结果的约束。

调用前必须检查最终实际发送的 Schema，确认：

- 它能够由当前 Provider Schema 确定性得到；
- 引用和依赖结构完整；
- 必填项、类型、枚举、范围、条件、数量等有效约束没有在转换过程中丢失或被放宽。

`title`、`description`、`$comment` 等只承担说明作用、且不影响验证结果的内容，可以按模型服务能力调整或省略。

如果某项正式约束无法用当前模型服务支持的 Schema 表达方式安全表示，本次适配失败，受影响的模型调用不得开始。

---

## 4. 上下游交接兼容性

交接检查以**本次实际交接面**为边界。

实际交接面包括：

- 本次实际传给下游的字段；
- 这些字段直接或递归引用、依赖的结构和约束。

交接检查同时确认：

1. 本次实际传递的数据满足下游输入要求；
2. 支撑这些字段的上游结构与下游对应结构兼容。

与本次交接字段没有引用或依赖关系的私有定义，不参与本次兼容性判断。

```text
实际交接字段
+ 这些字段可达的依赖结构
= 本次交接检查范围
```

交接兼容性遵循以下规则：

- 实际传递字段缺失，或其类型、必填关系、枚举、取值范围、条件、数量等有效约束与下游要求不兼容时，交接失败；
- 本次交接依赖的引用缺失、指向错误或无法解析时，交接失败；
- 与实际交接无关的私有定义变化，不影响本次交接；
- `title`、`description`、`$comment` 等不影响验证结果的说明内容，不参与兼容性判断；
- 不能通过比较整个 `$defs` 或整个上下游 Schema 是否完全相同，替代对实际交接面的检查。

---

## 5. 结构失败与局部成功

Schema 基础设施按实际结构处理结果形成以下事实：

| 结构事实 | 处理结果 |
| --- | --- |
| Schema 无法解析，或必要引用 / 依赖结构无效 | 依赖该结构的处理失败 |
| Provider Schema 无法无损转换为模型服务支持的表达 | 受影响的模型调用不启动 |
| 最终结果无法通过 Formal Schema 校验 | 该内容不是结构合法的正式结果 |
| 上下游实际交接面不兼容 | 受影响的数据不进入下游 |

单条、单项或局部结果失败时，只有当前能力合同和 Formal Schema 已经正式支持**局部成功**的表达，才能隔离失败部分并保留其他已经独立验证的结果。

结构修复只能处理能够确定性修正的 Schema 表达、引用、映射或组装问题，并保持原有正式语义。不得通过以下方式把结构失败改写成成功：

- 降低或删除 Formal Schema / Provider Schema 的正式约束；
- 改写科研判断以迎合结构；
- 静默删除失败项后宣称完整成功；
- 为单个业务节点建立绕过公共 Schema 处理的临时兼容路径。

结构处理结束后，基础设施只返回**结构合法结果或明确的结构失败事实**。结构失败之后是否恢复、重新执行或继续其他研究工作，由研究执行机制根据当前正式状态决定。
