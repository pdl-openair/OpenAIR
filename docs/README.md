## 2. Authority 关系

`01_核心设计/**` 定义 OpenAIR 通用设计。领域产品和 Workflow 在通用设计范围内补充各自的正式职责。工程与开发协作文档负责把这些设计落实为可执行、可验证、可维护的工程工作。

同一事实存在多份材料时，以其正式职责范围内更直接的设计合同为准；`待专项更新/` 中的材料用于后续校准，不作为当前正式设计依据。

工程规则（编码、门禁、安全、流程、测试、协作经验）的唯一权威是 `spec/`——含收编后的 `spec/collaboration/` 与 `spec/testing/`，规则与强制工具的映射以 `spec/enforcement/enforcement-matrix.md` 为索引；docs/ 下同类材料仅作历史版本或待校准参考。

## 3. 新人阅读方式

第一次进入项目时：

1. 从 [`01_核心设计/README.md`](01_核心设计/README.md) 建立系统整体认知；
2. 根据当前任务进入 [`02_产品与Workflow/`](02_产品与Workflow/README.md) 阅读对应领域设计；
3. 需要实现、运行或排查时进入 [`03_工程/`](03_工程/README.md)；
4. 需要施工、验收、发布或长程任务协作时进入 [`04_开发协作/`](04_开发协作/README.md)。

## 4. 文档维护

`docs/` 保留当前需要长期维护的正式文档，以及明确标记为“待专项更新”的仍有价值材料。历史版本由 Git 保存，不在目录中建立重复归档。
