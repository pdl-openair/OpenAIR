# 设计与技术文档编写

用于 GPT、Agent 或人新写、补充、重构设计与技术文档时。

> **文档是给人看的。写作者负责把复杂信息整理清楚，让读者更快形成正确理解，并据此做出正确判断、施工或验收。**

## 1. 写之前先确定读者和用途

先明确三件事：

- 谁会使用这份文档；
- 他打开文档时正在做什么；
- 读完后需要做什么判断或行动。

再决定内容和结构。

文件名直接说明用途，开头直接说明什么时候使用。

设计文档、TASKLIST、施工规范、经验文档和经验来源各自承担自己的职责。同一主题只保留一个正式负责位置。

---

## 2. 先读 Source Truth，再整理内容

写作前先确认当前有效依据：

- 已确认的需求和设计；
- 当前真实代码和运行行为；
- 用户已经明确的裁决；
- 当前有效的数据、测试和验证结果；
- 可参考但尚未确认的材料。

正文区分清楚：

- 当前有效事实；
- 已确认设计；
- 当前实现；
- 待确认事项；
- 历史材料。

材料之间有冲突时，先按当前 Authority 和 Source Truth 判断。仍无法确定的内容集中列为待裁决项。

不根据经验补造模块、接口、字段、流程、数字或结论。

---

## 3. 只写会帮助人理解和行动的信息

原始材料不是正文目录。

先完成：

> **筛选 → 去重 → 排序 → 提炼**

优先保留：

- 会改变读者判断的内容；
- 会影响施工或验收的规则；
- 容易理解错的边界；
- 多人必须统一理解的决定；
- 后续难以重新恢复的重要信息。

辅助信息按价值处理：

- 高价值：直接进入正文；
- 中价值：需要时补充；
- 低价值：删除或放到来源记录。

代码字段、Schema、日志、历史 Run、提交号和大量运行细节，只在确实影响读者判断时进入正文。

写作者承担整理成本，不把原始材料重新堆给读者。

---

## 4. 按人的真实工作顺序组织

正文优先按照读者实际使用过程展开。

常见顺序：

> **什么时候用 → 当前目标 → 核心设计 → 怎么工作 → 关键边界 → 怎么判断完成**

具体文档按实际任务调整，不机械套模板。

每一节：

- 标题直接说明用途；
- 先给关键结论；
- 再给支撑结论所需的细节；
- 一个问题在一个地方讲清楚。

README 只负责帮助人快速找到正确文档和阅读入口。

文件名、标题、正文内容和实际负责范围保持一致。

---

## 5. 用人的语言写

优先使用直接、准确、自然的中文。

技术字段、类名、函数名、节点名只在需要精确定位时补充。

复杂概念先说清它在实际工作中代表什么，再使用术语。

正文优先使用正向结论，例如：

> 模型负责专业判断，代码负责确定性组装。

控制以下 AI 常见写法：

| 常见问题 | 处理方式 |
|---|---|
| 同一观点反复解释 | 保留一个正式位置 |
| 为了完整补大量背景 | 只留影响理解和行动的信息 |
| 简单问题过度抽象 | 用最直接的业务或技术语言 |
| 按字段、Schema、源码结构写文档 | 改成人的理解和工作顺序 |
| 防御性、绕弯表达过多 | 直接写结论和规则 |
| 中英文黑话堆叠 | 中文说明为主，技术名词作补充 |
| 各章节分别生成、口径漂移 | 写前统一术语，写后做全文一致性检查 |
| 根据上下文自行补全“合理设计” | 只写有依据的事实和已确认设计 |

---

## 6. 图表只在能降低理解成本时使用

图适合表达：

- 架构；
- 流程；
- 状态变化；
- 模块关系；
- 数据流。

表格适合表达：

- 职责；
- 输入输出；
- 对比；
- 状态；
- 规则和边界。

一张图解决一个主要理解问题。

正文写图表背后的关键含义，不重复逐项复述图表内容。

---

## 7. AI 主写时，主动降低人的核查成本

AI 完成正文后，先自行检查：

- Source Truth 是否读全；
- 关键结论是否容易找到；
- 是否有重复和低价值内容；
- 是否出现无依据的新事实或新设计；
- 术语、对象、状态和边界是否前后一致；
- 各章节颗粒度是否一致；
- 图表与正文是否一致；
- 待裁决问题是否已经集中。

交给人核查时，只突出真正需要确认的事项。

人的时间优先用于：

- 判断关键事实；
- 裁决设计分歧；
- 确认重要边界。

不让人重新替 AI 做筛选、去重和总结。

---

## 8. 更新已有文档时做最小必要同步

先确认本次变化真正影响哪些内容。

只更新：

- 已改变的正式设计；
- 已改变的使用方法；
- 已改变的关键边界；
- 已改变的施工或验收依据；
- 已改变的阅读入口。

已经正确、稳定的内容继续保留。

新的长期经验进入对应经验文档；具体历史案例和证据进入经验来源。

---

## 定稿前检查

代入一个第一次接手任务的人，完整读一遍：

- [ ] 一眼知道这份文档什么时候用。
- [ ] 能快速找到最重要的结论。
- [ ] 内容顺序符合实际理解和工作过程。
- [ ] 正文只保留真正有价值的信息。
- [ ] 同一内容没有多处重复。
- [ ] 事实、设计、实现和待确认事项分得清。
- [ ] 表达直接、清楚，没有明显机器味和内部黑话。
- [ ] 图表确实帮助理解。
- [ ] 文件名、标题、内容和职责一致。
- [ ] 读完能够继续做正确的判断、施工或验收。

> **最终标准：读者拿到的是已经整理好的工作材料，可以直接理解和使用。**
