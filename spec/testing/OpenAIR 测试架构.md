# OpenAIR 测试架构

> 状态：已确认  
> 更新时间：2026-09-20  
> 职责：规定 OpenAIR 的长期测试证明责任，以及不同失败类别最低由哪一种测试责任主责。

---

## 1. 长期测试责任

测试架构按**失败风险**划分长期证明责任。

OpenAIR 使用六类长期测试责任：

| 测试责任 | 主要证明什么 |
| --- | --- |
| **确定性合同与不变量** | 明确规则、Schema、状态、身份、来源和其他可以确定性判定的正式合同 |
| **单个组件行为** | 一个 Production 组件独立承担的正式行为和副作用 |
| **跨组件与基础设施** | 多个 Production 责任之间的交接、事务、持久化、隔离和状态连续性 |
| **真实运行与韧性** | 真实 Provider、模型、runtime、恢复和资源条件下实际发生的行为 |
| **完整产品链验证** | 多个正式责任组合后最终形成的完整用户结果 |
| **科研 / Agent 能力评测** | 科研理解、证据判断、推理、建议和其他开放性质量 |

科研 / Agent 能力评测与软件测试并行。科研质量证据不能替代软件正确性证据，软件正确性证据也不能替代科研质量判断。

[经典注记] 本条 ≈ 测试金字塔/分层测试（Cohn《Succeeding with Agile》；Fowler TestPyramid）——差异：经典金字塔按“多 Unit 少 E2E”的成本比例分层，本表按失败风险的最低证明责任分层，不规定各层用例数量比例。

---

## 2. 最低测试主责

`minimum_owner` 表示：

> **某类失败最低由哪一种测试责任直接承担长期证明责任。**

同一 `failure_class` 由能够以最低必要范围、最直接且可诊断的方式证明该失败的测试责任主责。

| 受保护行为或失败 | `minimum_owner` |
| --- | --- |
| Formal Schema、状态值、稳定 ID、来源关系等明确规则被违反 | 确定性合同与不变量 |
| Resolver、Repository、Adapter 等单个组件没有履行自身正式责任 | 单个组件行为 |
| WorkUnit、Result、Artifact 等跨多个 Production 责任的交接或身份连续性错误 | 跨组件与基础设施 |
| Provider transport、模型任务、真实 runtime、恢复或资源实际使用事实错误 | 真实运行与韧性 |
| 完整产品装配没有形成正确的用户状态或最终结果 | 完整产品链验证 |
| 文献证据判断、科研综合、参数推荐等专业质量不足 | 科研 / Agent 能力评测 |

一个受保护结果同时存在多类失败风险时，应分别明确对应的 `failure_class` 和 `minimum_owner`。更高范围测试可以再次经过同一行为，用于证明组合后的产品结果，但不能替代相应 failure class 的最低主责。

只有真实 Provider、模型、runtime 或资源运行才能成立的事实，必须由真实运行取得证据；只有完整产品装配才能成立的用户结果，需要完整产品链验证；科研或 Agent 的开放性质量，需要正式 Eval 证据。

---

## 3. 测试责任与其他维度

测试架构只确定**证明责任及其最低主责**。

测试代码放在哪里，由测试代码架构根据受保护结果对应的 Production 责任边界决定；运行时使用什么环境、材料和依赖，由正式测试资产声明并由 Harness 执行。

因此：

```text
minimum_owner
≠
测试代码目录
≠
Harness 运行配置
```

例如，“真实运行与韧性”可以验证一个组件独立承担的行为，也可以验证多个 Production 责任共同形成的行为；实际代码归属仍由对应责任边界决定。

---

## 4. 架构扩展

新的 Workflow、领域、测试工具或运行环境优先使用现有六类测试责任。

只有出现长期独立的新 `failure_class`，而现有责任无法清楚表达其最低主责时，才扩展测试架构。

领域差异通过受保护结果、`failure_class`、测试对象、案例和判定标准表达，不通过新增同义测试层级表达。
